04 Callout Box System
Three types. Three colors. Each encodes a distinct meaning. A student who has read three articles should be able to identify the type from color alone before reading a word. Never create a fourth callout type without a documented learning-science reason.
Three callout types — visual reference color = meaning, always
Most-tested
The corridor width change from 1,200 mm to 1,500 mm ⟳ 2024. This is the number most likely to appear in "is this corridor compliant?" scenario questions.
ALE Watch
The 300 mm grab bar measurement is from the top of the toilet seat — not from the floor. The floor measurement (~750 mm) is a derived value, not the specification. Getting this reference point wrong produces wrong answers even when the number is correct.
Version alert — read first
Every number in this article reflects the 2024 IRR only. Values that changed from 2013 are marked ⟳ 2024. If your notes show a different number, the 2024 IRR governs for the exam.
Callout type rules usage constraints — enforce strictly
Most-tested (cobalt)
Appears after every summary table
Maximum 1 per section
Must contain a specific, bold exam value
1–2 sentences maximum. Never a paragraph.
ALE Watch (red)
Only for misconceptions that cause exam failure
Maximum 2 per article, total
States the wrong belief, immediately corrects it
Never used for general reminders
Version Alert (gold)
Appears exactly once — at the top of the article, before the first section
Never repeated inline. The ⟳ pill handles inline change signals.
Always contains the IRR year, the ⟳ explanation, and the "if different, 2024 governs" statement

05 Table Component
Tables are the highest-density learning element in the article. A student should be able to find the right exam value in under 3 seconds. This requires: cobalt-colored value column, gold-highlighted most-tested row, DM Mono source references, and inline ⟳ pills on changed values.
Table anatomy — all states every row type shown
Rendered output — Corridors section
ParameterValue (2024 IRR)Source
Corridors
Single wheelchair + ambulant ⟳ 2024 1,500 mm minimum C.5.1
Two wheelchairs simultaneous 1,800 mm minimum C.5.2
Turnabout dimensions ⟳ 2024 1,800 × 1,800 mm C.5.2
Max spacing between turnabouts 12,000 mm (12 m) C.5.2
Dead-end turnabout — max distance Within 3,500 mm C.5.3
Row types — exact styling rules each row type has distinct treatment
Column header row: DM Mono 9px, uppercase, tracking-widest, ink-muted color, background #FAFAF8 (one shade off warm-white), 0.5px bottom border. Height 36px.
Section header row (Quick Reference table only): Full-width row, background cobalt-light tinted at 8% opacity — use #1B3FC414. Text: DM Mono 9px uppercase, cobalt color. Use colSpan to fill all columns. This separates DOORS / CORRIDORS / TOILETS groups visually.
Most-tested row: Background signal-gold-light (#FFF8E6). Value column text color changes from cobalt to amber-800 (#92400E). Use sparingly — maximum 1 most-tested row per table section. Determined by isMostTested: true in the data.
Standard row: White background. Parameter text: Inter 13px, ink color. Value text: Inter 13px semi-bold, primary (cobalt) color. Source text: DM Mono 10px, ink-muted color.
Changed parameter: Append <WikiChangedPill /> inline after the parameter text when isChanged: true. The pill is Signal Gold, 9px DM Mono, "⟳ 2024".
Row borders: 0.5px border-light between rows. No border on final row. No vertical borders.
Cell padding: 9px top/bottom, 10px left/right on all cells.
Mobile: On screens <640px, hide the Source column (lowest priority). Parameter + Value survive. Add hidden sm:table-cell to source cells.
// src/components/wiki/WikiTable.tsx
import { WikiChangedPill } from './WikiChangedPill'
import { type WikiTableProps } from '@/types/wiki'
import { cn } from '@/lib/utils'

export function WikiTable({ caption, columns, rows, hasSourceColumn = true }: WikiTableProps) {
  return (
    <div className="my-6 rounded-lg border border-border overflow-hidden">
      {caption && (
        <p className="font-sans text-xs font-semibold text-ink px-3 py-2.5 border-b border-border bg-warm-white">
          {caption}
        </p>
      )}
      <div className="overflow-x-auto">
        <table className="w-full border-collapse">
          <thead>
            <tr className="bg-[#FAFAF8]">
              {columns.map((col, i) => (
                <th key={i} className={cn(
                  "font-mono text-[9px] font-medium uppercase tracking-widest text-ink-muted px-2.5 py-2 text-left border-b border-border",
                  i === columns.length - 1 && hasSourceColumn && "hidden sm:table-cell"
                )}>
                  {col}
                </th>
              ))}
            </tr>
          </thead>
          <tbody>
            {rows.map((row, i) => {
              if (row.isSectionHeader) return (
                <tr key={i} className="bg-[#1B3FC414]">
                  <td colSpan={columns.length} className="font-mono text-[9px] font-medium uppercase tracking-widest text-primary px-2.5 py-1.5">
                    {row.parameter}
                  </td>
                </tr>
              )
              return (
                <tr key={i} className={cn(
                  "border-b border-[#ECEAE4] last:border-b-0",
                  row.isMostTested && "bg-signal-gold-light"
                )}>
                  <td className="px-2.5 py-2.5 text-sm text-ink">
                    <span>{row.parameter}</span>
                    {row.isChanged && <WikiChangedPill className="ml-1.5" />}
                  </td>
                  {row.dimension && (
                    <td className="px-2.5 py-2.5 text-xs text-ink-muted">{row.dimension}</td>
                  )}
                  <td className={cn(
                    "px-2.5 py-2.5 text-sm font-semibold",
                    row.isMostTested ? "text-amber-800" : "text-primary"
                  )}>
                    {row.value}
                  </td>
                  {hasSourceColumn && (
                    <td className="px-2.5 py-2.5 font-mono text-[10px] text-ink-muted hidden sm:table-cell">
                      {row.source}
                    </td>
                  )}
                </tr>
              )
            })}
          </tbody>
        </table>
      </div>
    </div>
  )
}
06 Part Section Header
Every major section (Part 1: Entrances, Part 2: Doors...) opens with an eyebrow + H2 + subtitle. The eyebrow is the brand signal. The H2 is the anchor point for scanning. The subtitle previews the section's content so students can decide in 1 second whether to read it.

07 Changed-Value Pill ⟳
Every value that changed between the 2013 Illustrated IRR and the 2024 Revised IRR gets this pill inline. It is Signal Gold. It is the single most important visual signal in the article for protecting students from memorizing the wrong version. Appears in prose AND in table rows.
WikiChangedPill.tsx src/components/wiki/WikiChangedPill.tsx — tiny but critical
P1
Inline usage — in prose and in table rows
The minimum corridor width is 1,500 mm ⟳ 2024 — raised from 1,200 mm in the 2013 IRR. This is the most consequential change for typical building design.
In a table row:
ParameterValue
Approach space ⟳ 20241,800 × 1,800 mm
Style: Signal Gold background (#FFF8E6), amber border (0.5px, #FAD07A), amber-800 text (#92400E). DM Mono 9px, font-weight 500. Padding 1px 6px. Border-radius 3px.
Text content: Always "⟳ 2024" — never just "⟳" alone. The year anchors the context.
Position: Inline after the value or parameter, with margin-left 6px. Never on a new line.
Tooltip: Add title="Changed from 2013 Illustrated IRR" for accessibility. On hover, shows the old value if passed as a prop.

        "cursor-default select-none",
        className
      )}

    </span>
  )

08 Common Mistakes Cards
Memory research shows that presenting the wrong answer explicitly alongside the correct answer — with clear visual differentiation — produces stronger correction of misconceptions than presenting only the correct answer. The strikethrough-wrong / cobalt-correct format puts both in working memory simultaneously, which is exactly what forces the correction to stick.

02

09 Prose Typography Rules
These rules govern every word between the headers and the tables. They are not style preferences — they are learning interventions. Each formatting choice either reduces or increases cognitive load.
Body prose rules — what each element does and when to use it
ElementStyleWhen to useWhen NOT to use
Body paragraph Inter 15px, 400wt, ink, leading-7 All explanatory prose. Default. Max 5 sentences per paragraph. —
Bold font-semibold, ink color Specific exam-testable value: a number, a code section, a classification. Max 1 instance per 50 words. General emphasis. Topic words. Sentence-level importance. Anything that isn't a specific recall target.
Italic italic, ink color First use of a technical term. Official names of laws/codes. Foreign architectural terms. Stylistic emphasis. Terms used more than once (italic on first use only). Long phrases (>5 words).
Inline code DM Mono 12px, cream bg, cobalt text, rounded-sm px-1 Section references (C.5.1), code abbreviations (TGFA, FAR), specific formula terms. Long explanations. Never for full sentences.
H3 subheading Inter 16px, 600wt, ink, mt-8 mb-3 Sub-topics within a Part section. Use when a section covers 3+ distinct concepts. Labeling what's obvious from the prose. Never use generic H3s like "Background" or "Overview".
Breathing sentence Same as body, but <15 words, standalone paragraph After 2–3 dense paragraphs. Restates the key implication as a single sentence. Creates a cognitive pause. Padding or filler. Must contain a specific exam-relevant statement.
The Bold Test: Before bolding anything, ask: "If a student sees only this bold text in a scan, can they form a correct answer on an exam question?" If no — do not bold. If yes — bold. The F-pattern scan reads bold text before sentences. Everything bolded must be independently meaningful without its surrounding sentence.

11 Responsive & Dark Mode
Mobile-first breakpoint rules
Base (0–640px mobile): Single column. Tag pills wrap. Table source column hidden (hidden sm:table-cell). Callout boxes full width. Mistake cards stack vertically. Title font-size 24px.
sm (640px tablet+): Table source column visible. Title font-size 30px. Tag pills on single row.
lg (1024px desktop): Max-width 768px on article content. Left margin for potential sticky TOC in Phase 2.
Touch targets: All interactive elements minimum 44×44px. The ⟳ pill is display-only, not interactive, so no minimum size requirement.
Dark mode rules
All text: Use Tailwind's semantic tokens (text-foreground, text-muted-foreground) — never hardcoded text-ink directly in dark mode components. Add CSS variable mapping in globals.css.
Callout backgrounds: The cobalt-light, gold-light, red-light tints must be explicitly set with dark: variants — use 10% opacity cobalt/gold/red on dark backgrounds instead of light tint fills.
Tables: Section header rows use dark:bg-[#1B3FC420]. Most-tested row uses dark:bg-[#92400E20]. Row borders use dark:border-[#3A3835].
⟳ pill: Dark mode: dark:bg-[#92400E20] dark:text-[#F5C842] dark:border-[#A07020].
Cobalt Blue (#1B3FC4): Stays cobalt in both modes. Never invert to a different blue. The brand color is consistent.

13 Non-Negotiable Rules
These are not preferences. They are hard constraints. Any implementation that violates these rules must be revised before shipping — no exceptions.
Anti-patterns — never build these
PatternWhy it's banned
Fourth callout type (any new color)The three-type system works because it's learnable. A fourth type dilutes the semantic signal. New callout types require a documented learning-science reason and design review.
Signal Red for anything other than ALE Watch borderRed triggers anxiety responses. It is functional-only: ALE Watch callout border. Never on scores, never on failure states, never on body text.
Cobalt Blue on more than 15% of textBrand color is only meaningful when scarce. If 40% of text is cobalt, nothing reads as exam-critical. The cobalt signal fails when overused.
Syne font on anything other than the H1 titleSyne is the article title font only. Using it on H2, H3, or callouts makes the page feel noisy and breaks the typographic hierarchy.
Bold text as general emphasisBold is a specific signal: "this is a number or value to recall under exam pressure." Using it for general emphasis (important topics, interesting phrases) destroys the F-pattern scan value.
Decorative borders or backgrounds on prose sectionsProse sections are not cards. No border, no background, no box-shadow. The callout system is the only bordered element in the prose flow. Everything else is white space.
Animations, transitions, or hover effects on content elementsWiki articles are a calm reading environment. No hover effects on paragraphs, no transition on headers, no fade-in on tables. Interaction is reserved for the interactive quiz components (bp344-drill, etc.).
Gamification elements (badges, streaks, XP)These belong in the quiz engine, not in the wiki. A wiki article that rewards "reading" with a badge is toxic positivity and erodes trust in the platform's signal integrity.
More than 2 ALE Watch callouts per articleThe red signal must be rare. If 5 things in an article deserve an ALE Watch, the article has too many high-stakes warnings and the signal degrades. Prioritize the 2 most dangerous misconceptions only.
Hardcoded hex values in component filesAll color references must use Tailwind token classes or CSS variables. If a hex value appears in a .tsx file that isn't in the Tailwind config, it's a design system violation.
The governing question for every implementation decision: Does this make a student more likely to find the right exam value in less time, with less effort? If yes, build it. If no or uncertain, don't build it. Decoration is not design. Every element must earn its place.
