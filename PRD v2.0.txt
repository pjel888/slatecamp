## 1. Product Vision & Strategy

### The Problem

Board exam reviewers across professions (architecture, medicine, law, engineering) spend hundreds of hours with passive materials — reading highlighters, re-reading notes, staring at PDFs. Pass rates for first-time takers hover between 50–70% for most licensing exams. Existing review apps are ugly, generic, and provide zero adaptive intelligence.

### The Solution

Cerebro is a **cognitive-first test prep platform** that treats every review session as a data event. It measures what you know, identifies what you don't, adapts in real-time, and gives you an AI-powered study partner that never sleeps. For architecture board exams specifically, it includes 3D spatial interactivity for building systems, structures, and design theory.

### Core Philosophy

- **Active Recall over Passive Reading** — every interaction is a retrieval event
- **Spaced Repetition as infrastructure** — the algorithm decides when you see a question again, not you
- **Beautiful by default** — Dieter Rams said "good design is as little design as possible." The UI must disappear so the content can breathe
- **Profession-agnostic architecture** — architects first, but the data model supports any board exam domain

### Success Metrics (MVP)

| Metric | Target | Measurement |
|---|---|---|
| Daily Active Users | 500 within 3 months of launch | Supabase analytics |
| Average Session Duration | > 12 minutes | Event tracking |
| Question Completion Rate | > 80% per session | user_responses table |
| Free → Pro Conversion | > 5% | Stripe webhook logs |
| User-Reported Confidence | +20% after 30 days | In-app survey |

## 2. Target Users & Personas

### Primary: Architecture Board Exam Takers (Philippines ALE)

- **Age:** 22–30, fresh graduates or repeat takers
- **Context:** Reviewing while working as apprentice architects, often studying on commute (mobile-first)

- Individual tutors can sell question sets on the marketplace
- Institutions can license Cerebro as a white-label solution

## 4. Design System — "Rams Standard"

### Design Philosophy

Inspired by **Dieter Rams and the Braun design tradition**: "Less, but better." Every pixel must justify its existence. The interface should be invisible — the student's focus is the content, not the chrome.

**Rams' 10 Principles applied to Cerebro:**

1. **Innovative** — AI-adaptive, not just a flashcard app
2. **Useful** — every feature solves a real exam prep problem
3. **Aesthetic** — beautiful enough that students *want* to open it
4. **Understandable** — zero learning curve, self-explanatory UI
5. **Unobtrusive** — the design serves the content, never competes with it
6. **Honest** — no dark patterns, no fake urgency
7. **Long-lasting** — timeless visual language, not trendy
8. **Thorough** — every detail considered, down to the micro-interaction
9. **Environmentally friendly** — lightweight, fast, minimal resource usage
10. **As little design as possible** — back to purity, back to simplicity

### Color Palette

Derived from Braun product design language — achromatic foundation with deliberate, functional accent colors.

### Component Design Rules

**For AI Code Generation — enforce these patterns:**

1. **Buttons:** Solid fill for primary (`--signal-amber` bg, `--ink` text). Ghost/outline for secondary. No gradients. Subtle `transform: scale(0.98)` on `:active`.
2. **Cards:** `--card-bg` background, `1px solid --card-border`, `--card-shadow`. No rounded corner abuse — use `--radius-md` consistently.
3. **Inputs:** Bottom-border-only style in forms. Full border in search fields. Focus ring uses `--signal-amber` at 30% opacity.
4. **Transitions:** All interactive elements get `transition: all 150ms ease`. No bouncy animations. Motion should feel mechanical and precise, like a Braun dial.
5. **Icons:** Lucide icon set only. Stroke weight 1.5px. Size 20px default, 16px in compact contexts.
6. **Empty States:** Always design empty states. Use a single line of muted text + a primary CTA button. No sad-face illustrations.
7. **Loading:** Skeleton screens, never spinners. Pulse animation at 1.5s interval.
8. **Quiz UI (THE MOST IMPORTANT SCREEN):** Question text centered in viewport. Single-column, maximum `--max-width-content`. Answer choices as full-width touch targets (min 48px height). Clear visual distinction between selected, correct, incorrect states. Timer (if active) in top-right, monospace font, unobtrusive.

### Dark Mode

- Default to system preference via `prefers-color-scheme`
- User toggle persisted in Supabase user profile
- All color references through CSS variables — never hardcode hex values in components

### Responsive Breakpoints

```css
/* Mobile-first approach */
--bp-sm:  640px;   /* Large phone / small tablet */
--bp-md:  768px;   /* Tablet portrait */
--bp-lg:  1024px;  /* Tablet landscape / small laptop */
--bp-xl:  1280px;  /* Desktop */
--bp-2xl: 1536px;  /* Large desktop */
```

The **quiz-taking experience must be flawless on mobile**. Reviewing on a commute is a primary use case. Touch targets minimum 44px. Swipe gestures for next/previous question.

## 5. Technical Architecture

### Core Stack

| Layer | Technology | Notes |
|---|---|---|
| **Framework** | Next.js 15 (App Router) | Server Components by default. Client Components only when interactivity is required. |
| **Language** | TypeScript (strict mode) | `strict: true` in tsconfig. No `any` types. |
| **Database** | Supabase (PostgreSQL) | Hosted. Use `@supabase/ssr` for server-side cookie auth. |
| **Auth** | Supabase Auth | Email/password + Google OAuth. Magic link for onboarding. |
| **ORM/Types** | Supabase CLI generated types | `supabase gen types typescript --project-id <id> > types/supabase.ts` |
| **Vector Store** | Supabase pgvector | For PDF embeddings (RAG pipeline). |
| **Styling** | Tailwind CSS 4 + shadcn/ui | Custom theme matching Rams Standard palette. |
| **3D Engine** | Three.js + React Three Fiber | For architectural 3D interactivity module. |
| **AI Provider** | OpenAI API (GPT-4o) or Anthropic Claude | Configurable. Abstract behind an `ai-provider` service. |
| **Payments** | Stripe | Checkout Sessions + Customer Portal. Webhooks for tier management. |
| **File Storage** | Supabase Storage | PDF uploads, user avatars, 3D model assets. |
| **Deployment** | Vercel | Edge functions where possible. ISR for public pages. |
| **Analytics** | PostHog (self-hosted or cloud) | Event tracking, feature flags, session replay. |
| **Email** | Resend | Transactional emails (welcome, streak reminders, weekly reports). |

### Architecture Principles

**ENFORCE THESE IN EVERY AI SESSION:**

1. **Server Components First:** Default to RSC. Only add `'use client'` when you need `useState`, `useEffect`, event handlers, or browser APIs.
2. **Server Actions for Mutations:** All database writes go through Server Actions (`'use server'`). Never expose Supabase client-side for writes.
3. **No `localStorage` for Auth:** Use `@supabase/ssr` with cookie-based sessions. The server must know the auth state.
4. **No `useEffect` for Data Fetching:** Use RSC async functions or `use()` hook. Data fetching happens on the server.
5. **RLS on Everything:** Every Supabase table must have Row Level Security enabled. Policies must be defined before any feature is considered complete.
6. **Type Safety End-to-End:** Supabase-generated types flow from DB → Server → Client. No manual type definitions that drift.
7. **Edge-Ready:** Server Actions and API routes should work on Vercel Edge Runtime where possible.

## 6. Database Schema

**CRITICAL: Feed this exact schema to the AI. This prevents phantom columns and ensures relational integrity.**

```sql
-- =============================================================
-- EXTENSIONS
-- =============================================================
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "vector";

-- =============================================================
-- ENUMS
-- =============================================================
CREATE TYPE user_tier AS ENUM ('free', 'pro', 'max');
CREATE TYPE question_type AS ENUM ('mcq', 'true_false', 'identification', 'essay', 'matching', 'sequence');
CREATE TYPE difficulty_level AS ENUM ('easy', 'medium', 'hard', 'expert');
CREATE TYPE content_status AS ENUM ('draft', 'published', 'archived', 'flagged');

-- =============================================================
-- CORE TABLES
-- =============================================================

-- Users (extends Supabase auth.users)
CREATE TABLE public.profiles (
    id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
    email TEXT NOT NULL,
    full_name TEXT,
    avatar_url TEXT,
    tier user_tier DEFAULT 'free' NOT NULL,
    profession TEXT DEFAULT 'architecture',        -- 'architecture', 'medicine', 'law', 'engineering'
    exam_target TEXT,                               -- e.g., 'ALE 2026', 'ARE 5.0', 'USMLE Step 1'
    target_exam_date DATE,
    stripe_customer_id TEXT,
    stripe_subscription_id TEXT,
    ai_tokens_used INT DEFAULT 0,
    ai_tokens_limit INT DEFAULT 0,
    daily_streak INT DEFAULT 0,
    longest_streak INT DEFAULT 0,
    last_active_at TIMESTAMPTZ DEFAULT NOW(),
    preferred_theme TEXT DEFAULT 'system',          -- 'light', 'dark', 'system'
    onboarding_completed BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Exam Domains (profession-agnostic categorization)
CREATE TABLE public.exam_domains (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    profession TEXT NOT NULL,                       -- 'architecture', 'medicine', etc.
    name TEXT NOT NULL,                             -- e.g., 'Building Technology', 'Structural Engineering'
    slug TEXT UNIQUE NOT NULL,
    description TEXT,
    parent_domain_id UUID REFERENCES exam_domains(id),  -- Allows nested topics
    sort_order INT DEFAULT 0,
    icon_name TEXT,                                 -- Lucide icon identifier
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Question Banks (collections of questions)
CREATE TABLE public.question_banks (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    creator_id UUID REFERENCES profiles(id) ON DELETE SET NULL,
    title TEXT NOT NULL,
    description TEXT,
    profession TEXT NOT NULL,
    exam_domain_id UUID REFERENCES exam_domains(id),
    is_official BOOLEAN DEFAULT FALSE,              -- Platform-curated vs user-generated
    is_marketplace BOOLEAN DEFAULT FALSE,           -- Available for purchase
    price_cents INT DEFAULT 0,                      -- Price in cents (0 = free)
    currency TEXT DEFAULT 'PHP',
    status content_status DEFAULT 'draft',
    question_count INT DEFAULT 0,
    average_rating FLOAT DEFAULT 0,
    total_ratings INT DEFAULT 0,
    total_purchases INT DEFAULT 0,
    tags TEXT[] DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Questions
CREATE TABLE public.questions (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    bank_id UUID REFERENCES question_banks(id) ON DELETE CASCADE,
    exam_domain_id UUID REFERENCES exam_domains(id),
    creator_id UUID REFERENCES profiles(id) ON DELETE SET NULL,
    question_type question_type DEFAULT 'mcq',
    prompt TEXT NOT NULL,                           -- The question text (supports markdown)
    choices JSONB,                                  -- For MCQ: [{"id": "a", "text": "...", "is_correct": false}, ...]
    correct_answer TEXT NOT NULL,                   -- Answer key (choice ID for MCQ, text for identification)
    explanation TEXT,                               -- Shown after answering
    explanation_references TEXT[],                  -- Source citations
    difficulty difficulty_level DEFAULT 'medium',
    difficulty_rating FLOAT DEFAULT 0.5,            -- IRT difficulty parameter (0-1 scale)
    discrimination_rating FLOAT DEFAULT 1.0,        -- IRT discrimination parameter
    has_3d_component BOOLEAN DEFAULT FALSE,         -- Links to 3D interactive element
    three_d_model_ref TEXT,                         -- Reference to 3D asset
    image_urls TEXT[] DEFAULT '{}',                 -- Question images
    tags TEXT[] DEFAULT '{}',
    times_answered INT DEFAULT 0,
    times_correct INT DEFAULT 0,
    status content_status DEFAULT 'published',
    sort_order INT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- =============================================================
-- USER ACTIVITY & SRS
-- =============================================================

-- User Responses (every answer attempt is logged)
CREATE TABLE public.user_responses (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    question_id UUID REFERENCES questions(id) ON DELETE CASCADE NOT NULL,
    session_id UUID,                               -- Groups responses into a test session
    selected_answer TEXT NOT NULL,
    is_correct BOOLEAN NOT NULL,
    response_time_ms INT,                          -- Time to answer in milliseconds
    confidence_level INT,                          -- 1-5 self-reported confidence (optional)
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Test Sessions (a group of questions taken together)
CREATE TABLE public.test_sessions (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    bank_id UUID REFERENCES question_banks(id),
    exam_domain_id UUID REFERENCES exam_domains(id),
    session_type TEXT DEFAULT 'practice',           -- 'practice', 'timed_test', 'review', 'ai_adaptive'
    total_questions INT DEFAULT 0,
    correct_answers INT DEFAULT 0,
    total_time_ms INT DEFAULT 0,
    score_percentage FLOAT,
    difficulty_mode TEXT DEFAULT 'mixed',           -- 'easy', 'medium', 'hard', 'mixed', 'adaptive'
    completed_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- SRS Queue (Spaced Repetition Schedule)
CREATE TABLE public.srs_queue (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    question_id UUID REFERENCES questions(id) ON DELETE CASCADE NOT NULL,
    next_review_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    interval_days FLOAT DEFAULT 1,                 -- Can be fractional (e.g., 0.5 = 12 hours)
    ease_factor FLOAT DEFAULT 2.5,                 -- SM-2 ease factor
    repetition_count INT DEFAULT 0,
    lapses INT DEFAULT 0,                          -- Number of times forgotten
    last_quality INT,                              -- Last SM-2 quality score (0-5)
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(user_id, question_id)
);

-- =============================================================
-- AI & DOCUMENTS
-- =============================================================

-- Uploaded Documents (PDF ingestion)
CREATE TABLE public.documents (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    filename TEXT NOT NULL,
    file_path TEXT NOT NULL,                        -- Supabase Storage path
    file_size_bytes INT,
    page_count INT,
    status TEXT DEFAULT 'processing',              -- 'processing', 'ready', 'error'
    profession TEXT,
    exam_domain_id UUID REFERENCES exam_domains(id),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Document Chunks (for RAG — "Knowledge Bricks")
CREATE TABLE public.document_chunks (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    document_id UUID REFERENCES documents(id) ON DELETE CASCADE NOT NULL,
    chunk_index INT NOT NULL,
    content TEXT NOT NULL,
    embedding VECTOR(1536),                        -- OpenAI text-embedding-3-small dimension
    page_number INT,
    metadata JSONB DEFAULT '{}',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- AI Conversations (Socratic Tutor chat history)
CREATE TABLE public.ai_conversations (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    question_id UUID REFERENCES questions(id),     -- Context question (if triggered by wrong answer)
    messages JSONB DEFAULT '[]',                   -- [{role: 'user'|'assistant', content: '...', timestamp: '...'}]
    tokens_used INT DEFAULT 0,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- =============================================================
-- MARKETPLACE
-- =============================================================

-- Marketplace Purchases
CREATE TABLE public.marketplace_purchases (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    buyer_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    bank_id UUID REFERENCES question_banks(id) ON DELETE CASCADE NOT NULL,
    amount_cents INT NOT NULL,
    currency TEXT DEFAULT 'PHP',
    stripe_payment_intent_id TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(buyer_id, bank_id)
);

-- Question Bank Ratings
CREATE TABLE public.bank_ratings (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    bank_id UUID REFERENCES question_banks(id) ON DELETE CASCADE NOT NULL,
    rating INT CHECK (rating >= 1 AND rating <= 5),
    review_text TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(user_id, bank_id)
);

-- =============================================================
-- ANALYTICS (pre-computed for dashboard performance)
-- =============================================================

-- Daily User Stats (materialized by cron or trigger)
CREATE TABLE public.daily_user_stats (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    user_id UUID REFERENCES profiles(id) ON DELETE CASCADE NOT NULL,
    date DATE NOT NULL,
    questions_attempted INT DEFAULT 0,
    questions_correct INT DEFAULT 0,
    total_study_time_ms INT DEFAULT 0,
    domains_studied TEXT[] DEFAULT '{}',
    streak_maintained BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(user_id, date)
);

-- Domain Mastery (per-user, per-domain performance)
```

### D. Spaced Repetition System (SRS)

**Algorithm: SM-2 (Pro) / IRT-Enhanced (Max)**

```typescript
// SM-2 Implementation (Pro tier)
function calculateNextReview(
  quality: number,        // 0-5 (0 = complete blackout, 5 = perfect recall)
  repetitions: number,
  easeFactor: number,
  interval: number
): { interval: number; easeFactor: number; repetitions: number } {

  let newEF = easeFactor + (0.1 - (5 - quality) * (0.08 + (5 - quality) * 0.02));
  newEF = Math.max(1.3, newEF);  // Minimum ease factor

  if (quality < 3) {
    // Failed — reset
    return { interval: 1, easeFactor: newEF, repetitions: 0 };
  }

  let newInterval: number;
  if (repetitions === 0) newInterval = 1;
  else if (repetitions === 1) newInterval = 6;
  else newInterval = Math.round(interval * newEF);

  return { interval: newInterval, easeFactor: newEF, repetitions: repetitions + 1 };
}

// Quality scoring from user response
function getQuality(isCorrect: boolean, responseTimeMs: number, confidence?: number): number {
  if (!isCorrect) return 1;
  if (responseTimeMs < 5000 && confidence >= 4) return 5;  // Fast + confident
  if (responseTimeMs < 10000) return 4;                     // Moderate speed
  if (responseTimeMs < 20000) return 3;                     // Slow but correct
  return 3;
}
```

```typescript
async function getRelevantContext(questionText: string, userId: string): Promise<string> {
  // 1. Embed the question
  const embedding = await generateEmbedding(questionText);

  // 2. Search user's document chunks
  const { data: chunks } = await supabase.rpc('match_documents', {
    query_embedding: embedding,
    match_threshold: 0.7,
    match_count: 5,
    filter_user_id: userId
  });

  // 3. Concatenate relevant chunks
  return chunks.map(c => c.content).join('\n\n---\n\n');
```

**Supabase Function for vector search:**

```sql
CREATE OR REPLACE FUNCTION match_documents(
  query_embedding VECTOR(1536),
  match_threshold FLOAT,
  match_count INT,
  filter_user_id UUID
) RETURNS TABLE (id UUID, content TEXT, similarity FLOAT) AS $$
BEGIN
  RETURN QUERY
  SELECT
    dc.id,
    dc.content,
    1 - (dc.embedding <=> query_embedding) AS similarity
  FROM document_chunks dc
  JOIN documents d ON dc.document_id = d.id
  WHERE d.user_id = filter_user_id
    AND 1 - (dc.embedding <=> query_embedding) > match_threshold
  ORDER BY dc.embedding <=> query_embedding
  LIMIT match_count;
END;
$$ LANGUAGE plpgsql;
```

### Item Response Theory (IRT) — Max Plan

The predictive engine uses a 2-Parameter Logistic (2PL) IRT model.

```
P(correct | θ, a, b) = 1 / (1 + exp(-a * (θ - b)))

Where:
  θ = student ability (latent trait, estimated per domain)
  a = question discrimination (how well it separates high/low ability)
  b = question difficulty (the ability level at which P(correct) = 0.5)
```

**Adaptive Question Selection:**

```typescript
function selectNextQuestion(
  userTheta: number,
  availableQuestions: Question[],
  answeredIds: Set<string>
): Question {
  // Filter out already-answered questions
  const candidates = availableQuestions.filter(q => !answeredIds.has(q.id));

  // Find question where P(correct) ≈ 0.75 (flow state target)
  const targetDifficulty = userTheta - Math.log(3) / candidates[0].discrimination_rating;

  // Sort by proximity to target difficulty
  candidates.sort((a, b) =>
    Math.abs(a.difficulty_rating - targetDifficulty) -
    Math.abs(b.difficulty_rating - targetDifficulty)
  );

  return candidates[0];
}
```

**Theta Update After Response:**

```typescript
function updateTheta(
  currentTheta: number,
  question: Question,
  isCorrect: boolean
): number {
  const { difficulty_rating: b, discrimination_rating: a } = question;
  const p = 1 / (1 + Math.exp(-a * (currentTheta - b)));

  // Newton-Raphson single step
  const information = a * a * p * (1 - p);
  const delta = (Number(isCorrect) - p) / information;

  return currentTheta + delta;
}
```

### Predictive Score Modeling (Max Plan)

Using accumulated `theta` values across domains and response history, predict the user's likely exam score:

```typescript
function predictExamScore(domainMasteries: DomainMastery[]): {
  predictedScore: number;
  confidence: number;
  weakDomains: string[];
  strongDomains: string[];
} {
  // Weighted average of theta values, weighted by domain importance in actual exam
  const weightedTheta = domainMasteries.reduce((sum, dm) => {
    return sum + dm.theta * getExamWeight(dm.exam_domain_id);
  }, 0);

  // Convert theta to percentage score (calibrated against historical exam data)
  const predictedScore = thetaToPercentage(weightedTheta);

  // Confidence based on number of questions answered
  const totalAnswered = domainMasteries.reduce((sum, dm) => sum + dm.total_attempted, 0);
  const confidence = Math.min(0.95, 0.3 + (totalAnswered / 500) * 0.65);

  // Identify weak and strong domains
  const sorted = [...domainMasteries].sort((a, b) => a.mastery_score - b.mastery_score);
  const weakDomains = sorted.slice(0, 3).map(dm => dm.exam_domain_id);
  const strongDomains = sorted.slice(-3).map(dm => dm.exam_domain_id);

  return { predictedScore, confidence, weakDomains, strongDomains };
}
```

```
PROJECT: Cerebro — AI-Adaptive Board Exam Prep Platform
STACK: Next.js 15 (App Router), TypeScript strict, Supabase, Tailwind CSS 4, shadcn/ui
DESIGN: Rams Standard — Braun-inspired minimal aesthetic. Achromatic palette (warm whites, greys, charcoal) with functional amber/green/red accents. No gradients, no shadows heavier than 0 1px 3px rgba(26,26,26,0.06). Transitions at 150ms ease.

RULES:
1. Server Components by default. Only add 'use client' when useState/useEffect/event handlers are needed.
2. Server Actions for all database mutations. Never expose Supabase writes client-side.
3. Use @supabase/ssr for auth. NEVER use localStorage for auth state.
4. No useEffect for data fetching. Use RSC async or the use() hook.
5. RLS is enabled on ALL tables. Check policies before adding features.
6. TypeScript strict mode. No 'any'. Use Supabase-generated types.
7. Tailwind only for styling. No inline styles. No CSS modules.
8. shadcn/ui for base components. Customize colors via CSS variables.
9. Lucide icons only. Stroke 1.5px, 20px default size.
10. Mobile-first responsive design. Touch targets min 44px.

DATABASE: See PRD.md Section 6 for complete schema. Do NOT create columns not in the schema.

QUIZ UI: Single column, max-width 720px, centered. Full-screen immersive. Optimistic UI for answers.
```
