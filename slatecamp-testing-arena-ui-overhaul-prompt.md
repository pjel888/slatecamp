## THE DESIGN MANDATE: "THE LINEAR STANDARD"

The testing interface must embody these principles, derived from Linear's design philosophy and adapted for educational testing:

### 1. Content-First, Chrome-Second
In Linear, the issue content dominates. The navigation, toolbars, and metadata are SUBORDINATE — present but invisible until needed. In SlateCamp's testing interface:
- The QUESTION is the absolute center of attention. Everything else is secondary.
- UI chrome (question number, progress, timer, tools) lives in a thin, structured header or margin — NEVER competing with the question.
- The option buttons are the SECOND most prominent element — clean, scannable, instantly tappable.
- Everything else (flag, notes, navigation) is quietly available without demanding attention.

### 2. 8px Grid, No Exceptions
Linear uses an 8px spacing scale. Every margin, padding, and gap is a multiple of 8 (8, 16, 24, 32, 48, 64). This creates subconscious RHYTHM — the interface feels "right" even if the user can't articulate why.

**Applied to testing:**
- Question card padding: `p-6` (24px) or `p-8` (32px) — generous for reading comfort
- Option button padding: `p-4` (16px) vertically, `px-5` (20px) horizontally
- Gap between options: `gap-3` (12px) or `gap-4` (16px)
- Header height: `h-12` (48px) or `h-14` (56px)
- Sidebar width (if used): `w-64` (256px) or `w-72` (288px)

### 3. Achromatic Base, Surgical Color
Linear's interface is almost entirely monochrome — black, white, and grays. Color appears ONLY for: active states, status indicators, and primary actions. In the testing interface:

| Color | Usage | Tailwind |
|-------|-------|---------|
| White | Page background, card backgrounds | `bg-white` |
| Gray-50 | Muted surfaces, secondary areas, question navigator bg | `bg-gray-50` |
| Gray-100 | Hover states on options, pressed states | `bg-gray-100` |
| Gray-200 | Borders — THE structural element | `border-gray-200` |
| Gray-500 | Secondary text, labels, metadata | `text-gray-500` |
| Gray-900 | Primary text, question text | `text-gray-900` |
| Blue-600 | PRIMARY ONLY: Submit button, selected option indicator, progress bar fill, active tab | `bg-blue-600`, `text-blue-600`, `border-blue-600` |
| Green-600 | SEMANTIC ONLY: Correct answer (in review mode) | `text-green-600` |
| Amber-500 | SEMANTIC ONLY: Flagged question indicator | `text-amber-500` |
| Red-500 | SEMANTIC ONLY: Incorrect answer (in review mode), critical errors | `text-red-500` |
| **FORBIDDEN** | Purple, teal, indigo, pink, orange as UI colors (not semantic) | — |

### 4. Hairline Borders as Structure
Linear uses 1px borders as its PRIMARY method of creating visual structure — not shadows, not background contrast, not thick dividers. The testing interface should:
- Use `border border-gray-200` on all cards and containers
- Use `border-b border-gray-200` for horizontal dividers (header bottom, between sections)
- Use `divide-y divide-gray-200` for lists of options
- NEVER use thick borders (`border-2`+) except for selected state indicators
- NEVER use `shadow-lg` or `shadow-xl` on cards. `shadow-none` at rest, `shadow-sm` on hover maximum.

### 5. Tight, Precise Typography
Linear's typography is notably SMALLER and TIGHTER than typical consumer apps. This signals professionalism and density — "this tool respects your intelligence."

| Element | Size | Weight | Color | Tracking |
|---------|------|--------|-------|----------|
| Question number + metadata | 12px (`text-xs`) | Semibold (600) | `text-gray-500` | Normal |
| Question stem text | 16px (`text-base`) | Normal (400) or Medium (500) | `text-gray-900` | Normal |
| Option text | 14-15px (`text-sm`) | Normal (400) | `text-gray-800` | Normal |
| Option label (A, B, C, D) | 13px | Semibold (600) | `text-gray-400` | Wider |
| Timer display | 13px (`text-sm`) | Mono, Medium (500) | `text-gray-500` | Mono |
| Button labels | 13px (`text-sm`) | Semibold (600) | Varies | Slight tracking |
| Page title ("Quiz: Structural Systems") | 16-18px | Semibold (600) | `text-gray-900` | Tight (-0.01em) |
| **FORBIDDEN** | `text-2xl`+ for any UI chrome, `text-3xl`+ for anything | — | — | — |

### 6. Docked Tools, Never Floating
In a professional testing interface, tools (flag, notes, calculator, settings) must be STRUCTURALLY positioned — they push content, never overlap it.

**Acceptable patterns:**
- **Thin top header:** Question number, progress bar, timer, exit button — all in one line, `h-12`, fixed at top
- **Inline toolbar:** Flag/notes buttons INSIDE the header or BELOW the question area as a subtle row
- **Side panel (right):** Question navigator grid, notes panel — opens by pushing the question area, not overlaying it
- **Keyboard shortcuts:** Most tools accessible via keyboard without any visible toolbar at all

**FORBIDDEN patterns:**
- Floating action bar (`fixed bottom-4 left-1/2 -translate-x-1/2`) — blocks content
- Bottom sheet modal (slides up from bottom) — mobile pattern, not desktop
- Sticky footer bar that eats vertical space on every question
- FABs (Floating Action Buttons) anywhere in the testing interface

### 7. Micro-Rounded or Sharp Corners
Linear uses very subtle border-radius — approximately 4-6px on most elements, with some sharper elements at 2px.

| Element | Radius | Tailwind |
|---------|--------|---------|
| Cards, containers | 6px | `rounded-md` |
| Buttons | 6px | `rounded-md` |
| Option buttons | 6px | `rounded-md` |
| Inputs | 6px | `rounded-md` |
| Badges, pills | Full | `rounded-full` (exception — these are naturally round) |
| Modals, dialogs | 8px | `rounded-lg` (ONLY for overlays) |
| **FORBIDDEN** | `rounded-xl` (12px), `rounded-2xl` (16px), `rounded-3xl` on any element | — |

## FINAL REMINDERS

1. **AUDIT EVERYTHING FIRST.** Phase 1 reads every file. You need the complete picture before touching a single class.

2. **STRUCTURE BEFORE POLISH.** Kill the floating toolbar and bottom sheets (Phase 3) BEFORE polishing typography and colors (Phase 4). Structure is load-bearing. Polish is cosmetic.

3. **PRESERVE ALL LOGIC.** This is a VISUAL overhaul. If a handler works, it stays. If a state machine works, it stays. You're changing the skin, not the skeleton.

4. **THE LINEAR STANDARD IS THE BENCHMARK.** When in doubt, ask: "Would this element exist in Linear's app?" If no → remove it. "Would this color appear in Linear?" If no → gray or blue.

5. **AI-GENERATED UI HAS TELLS.** Mixed radii, arbitrary colors, inconsistent spacing, oversized everything, shadows on flat surfaces, floating elements. Hunt these tells and kill them systematically.

6. **THE QUESTION IS KING.** In the final interface, 70% of the screen should be the question and options. 20% should be subtle chrome (header, navigation). 10% should be available-on-demand tools (navigator, notes). If the chrome is competing with the content, the design has failed.
