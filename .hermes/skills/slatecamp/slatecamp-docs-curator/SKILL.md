# Slatecamp Docs Curator

## When to Use

Use when creating or updating docs, `.ai` notes, architecture maps, handoffs, or changelogs.

## Procedure

1. Verify facts from current files and Git history.
2. Remove stale or duplicate instructions.
3. Keep docs short and operational.
4. Prefer exact paths, commands, and decisions over broad prose.
5. Separate confirmed facts from open questions.

## Pitfalls

- Turning docs into a graveyard of old assumptions.
- Writing inspirational text instead of operating guidance.
- Updating docs without checking the code.

## Output

A compact doc update plus a summary of what changed and why.
