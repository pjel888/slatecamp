# Decision Records

Use decision records for architecture choices that will affect future work.

## When to create one

- Framework or library choice.
- Data model or migration strategy.
- Auth/security policy.
- Deployment architecture.
- Major UI/system design convention.
- Refactor that changes module boundaries.

## ADR format

```text
# ADR-000: Title

Date:
Status: Proposed | Accepted | Superseded

## Context

## Decision

## Consequences

## Alternatives considered

## Verification plan
```

## Rule

A decision record should clarify tradeoffs. It should not become a long essay.
