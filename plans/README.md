## Audit summary

Six parallel read-only audit passes (security, correctness, performance, architecture, tests, DX/deps/docs) produced ~60 raw findings. After vetting against live code, deduping cross-category overlaps, and downgrading by-design behavior, **18 plans** survived — and all 18 have been applied.

The most impactful patterns (each touched by ≥2 categories):

- **The mastery write path was the single highest-risk surface in the app.** It carried a correctness bug (concurrent RMW lost updates — C3/C4), an architecture smell (no owning module — ARCH-01/02), a test gap (no integration test — TC-02), and lived next to the SRS `repetitions` bug (C1). Plans 001 + 012 + 013 together fix the SRS bug, characterize the path with 28 tests, and consolidate three racing hooks into a single SELECT + single UPSERT.
- **The wiki article render path was the second-highest-risk surface.** Two stored-XSS sinks (SEC-01, SEC-02), unbounded MDX regex exposure (C14), the Mermaid/DoorHinge3D/three.js bundle regression (perf), and zero adversarial-input tests (TC-03). Plans 002 + 003 + 005 + 006 + 007 close the XSS sinks and remove the bundle regression.
- **Bundle weight on the wiki tree** (Mermaid + DoorHinge3D + isomorphic-dompurify all statically imported into every article) was the single biggest performance regression vs the rest of the codebase — fixed by Plans 005, 006, 007, 008.
