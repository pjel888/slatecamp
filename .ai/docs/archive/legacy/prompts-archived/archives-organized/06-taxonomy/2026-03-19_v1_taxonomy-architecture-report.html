01 — Executive Verdict

v5.0 is not a data upgrade.
It is a product upgrade.

The taxonomy is no longer just a labeling system for quiz questions. With bloom_level, difficulty, exam_frequency, typical_question_formats, three_d_lab_linked, is_computation_heavy, prerequisite relationships, mastery_criteria, and typed wiki_items — the taxonomy has become the intelligence engine that can drive every adaptive feature SlateCamp has ever planned.

The Governing Principle
Every architecture decision was already validated by the question: "Does this make a student more likely to win their Licensure Exam?" The taxonomy v5.0 answers that question with data instead of intuition — for every node, on every topic, for every student interaction. The product must now use that data.
What Is Definitively Better

v5.0 is categorically stronger than every previous version

v3.5 had exam_frequency on only 54 of 164 subtopics (33%). v5.0 has it on all 172. v3.5 had no bloom_level, no difficulty, no question formats, no prerequisites, no mastery_criteria — and untyped wiki_content strings. v5.0 has all of these, fully populated on every leaf node. No existing Philippine ALE review platform has this kind of structured, machine-readable pedagogical metadata on their content — not even close.

Critical Factual Corrections

Errors in previous versions that would have cost students the exam

The seismic zone error (Zone 4 → Zone 2 per NSCP 2015) and the CPD correction (15 → 45 units per 3-year period) are the kind of factual errors that, left uncorrected, cause students to answer ALE questions with the wrong information. These have been fixed across all affected nodes: ALE-STRC-005-03, ALE-LAWS-005-04, ALE-PRAC-001-01, ALE-PRAC-001-03, ALE-LAWS-001-03. This alone justifies the upgrade.

The ALE-LAWS Architecture Decision

Cross-reference layer with zero exam weight — the right call

Designating ALE-LAWS as a cross-reference-only subject (is_cross_ref_only = true, exam weight = 0%) is architecturally correct. Law questions are distributed across Areas A, B, and C — ALE-LAWS is a navigation layer, not a testable subject. The trigger that prevents questions from tagging to ALE-LAWS nodes enforces this at the database level, permanently. Wiki articles can still be created for ALE-LAWS nodes. This is exactly right.

New Content — ALE-LAWS-006

Allied Professions & Emerging Practice Laws — long overdue

The addition of RA 8534 (Interior Design), RA 8549 (Landscape Architecture), RA 10587 (Environmental Planning), RA 11032 (Ease of Doing Business), and RA 11313 (Safe Spaces Act) as a new topic fills a gap that many ALE candidates miss. These laws define the boundary of architectural scope and the practice context that increasingly appears in professional practice questions.

02 — Schema Analysis

Every new field analyzed:
what it stores, what it drives.

The 8 new data fields in v5.0 are not supplementary — they are the data contracts that the product architecture's planned features depend on. Each field examined below in terms of what it stores, which feature it was designed for, and what additional opportunities it creates.

bloom_level
ENUM: remember | understand | apply | analyze
Bloom's cognitive taxonomy level. Populated on all 172 subtopics. Determines the cognitive demand of a question, not just its topic tag.
Powers
Camp Trail progression sequencing (novice → expert). Adaptive difficulty calibration. Cognitive development tracking beyond raw accuracy. Camp Mode vs Storm Mode question selection stratification. Feynman Teach-Back depth evaluation.
difficulty
SMALLINT: 1 (Foundational) → 4 (Expert)
SME-calibrated difficulty. 1=First-takers should get this right. 4=Multi-step reasoning, high discriminating power. All 172 subtopics populated.
Powers
IRT weighting calibration. Endurance Cycle difficulty ramping. Camp Trail progression within a subject. Topnotcher identification (difficulty 3–4 accuracy distinguishes them). Quiz engine adaptive session generation.
exam_frequency
ENUM: low | medium | high
SME-assessed ALE exam frequency. Was 54/164 in v3.5 (33%). Now 172/172 (100%). Every subtopic now has a frequency signal.
Powers
Blindspot Protocol priority targeting — Red nodes that are high-frequency get targeted first. Camp Trail content ordering — high-frequency topics front-loaded. Free tier content cap — surface high-frequency nodes first. Readiness Score weighting — high-frequency subtopic mastery contributes more.
typical_question_formats
TEXT[]: mcq_recall | mcq_application | mcq_calculation | design_application
Array of question formats the ALE typically uses for this subtopic. Fully populated across all 172 subtopics.
Powers
Question bank coverage auditing — ensures question bank matches format distribution per subtopic. Camp Trail step design — calculation subtopics prescribe longer sessions. Quiz engine contextual variation — confirms which contexts are valid for a node. Assessment quiz balancing — ensures format diversity per subject.
is_computation_heavy
BOOLEAN DEFAULT false
TRUE for subtopics where ALE items require multi-step calculation. Primarily ALE-STRC (structural) and ALE-UTIL (utilities) subtopics. SPP fee calculations in ALE-PRAC also qualify.
Powers
Camp Trail session time budget — computation sessions get more time allocation. Quiz engine time-per-question budget — allows longer avg_time_ms for calculation items without triggering Endurance warnings. 3D Lab routing — computation-heavy nodes benefit from parametric visualization. Pacing Gauge calibration per subject.
three_d_lab_linked
BOOLEAN DEFAULT false
TRUE if a 3D Lab interactive module exists or is planned. Primarily across ALE-STRC, ALE-MATL, ALE-UTIL, ALE-DSGN spatial subtopics.
Powers
Wiki article sidebar — shows "Open in 3D Lab" CTA when true. Camp Trail step builder — suggests lab step alongside quiz step for linked nodes. Blindspot Protocol routing — spatially complex Red nodes route to 3D Lab before quiz. 3D Lab priority build queue — all true nodes are candidates for the top-10 module list.
wiki_items
JSONB: typed objects (heading | fact | definition | formula | code_provision | detail | exam_tip | cross_ref | warning)
Replaces untyped wiki_content strings. Each item has a type that controls rendering. All 172 subtopics populated. This is the structured authoring brief for SMEs.
Powers
Wiki article renderer — renders headings, tips, warnings, formulas distinctively rather than as flat text. Elaborative Interrogation — exam_tip items become EI_PROMPT candidates. SME workflow — structured brief dramatically accelerates article authoring. AI Reference Assistant RAG — typed items allow targeted retrieval by type. Warning-type items surface as flagged corrections automatically.
mastery_criteria
JSONB {threshold_pct, critical_topics, note} — subject level (level=1) only
Subject-level mastery specification with threshold accuracy, critical topics for passing, and SME study guidance. All 9 subjects populated.
Powers
Readiness Score per-subject pass/fail prediction — does this student meet the subject threshold? Camp Trail completion gate — a trail is not "done" until mastery_threshold_accuracy_pct is reached. Score Reveal screen — sub-score coloring based on threshold proximity. Trail Recommendation Engine — critical_topics drive the "Week 1 focuses on X" recommendation reasoning. SME study notes feed into Dashboard guidance copy.
taxonomy_prerequisites
Junction table: subtopic_id → prerequisite_id (bidirectional)
Junction table (not a TEXT array) so both forward and reverse queries work. Forward: "what must be mastered before X?" Reverse: "if X regresses, what other subtopics are at risk?"
Powers
Camp Trail sequencing — enforce learning order at the subtopic level. Blindspot Protocol cascade — if ALE-UTIL-001-02 goes Red, flag ALE-UTIL-001-04 (DFU table). Progressive unlocking — gate harder subtopics behind prerequisite mastery thresholds. Curriculum design tool — SMEs can map prerequisite graph visually. Retaker trail design — start with prerequisite gaps, not arbitrary order.
The ALE-LAWS Cross-Reference Architecture
taxonomy_cross_references is the bidirectional law-to-content graph. 47+ pairs from ALE-LAWS subtopics to substantive subject subtopics. This is what enables bidirectional wiki linking: when reading an ALE-DSGN article on accessible design, "Governing law: BP 344" appears automatically. When reading ALE-LAWS-002-03 (BP 344), "Applied in: Accessible Design (ALE-DSGN-002-01)" appears automatically. No other Philippine ALE platform has this — it turns the laws subject from an orphaned cross-reference into a fully navigable knowledge graph.
03 — Subject Map

All 9 subjects analyzed:
weight, mastery criteria, and implications.

The taxonomy defines 9 subjects with explicit PRC exam area weights, mastery threshold criteria, and critical topic lists per subject. This is the structural foundation of the Readiness Score and every adaptive feature built on it.

ALE-HIST
History of Architecture
Area A · ~10.5%
~35% within Area A · Mastery threshold: 75%
Critical: Pre-Colonial PH (HIST-003), Contemporary PH (HIST-005–006). Pritzker Laureates (HIST-005-04) high-frequency. Philippine architecture most under-studied.
ALE-THEO
Theory of Architecture
Area A · ~7.5%
~25% within Area A · Mastery threshold: 70%
Critical: Organizing principles (THEO-001), Tropical design (THEO-004). BIM correctly moved here from Practice in v5.0 restructuring.
ALE-PLAN
Theory & Principles of Planning
Area A · ~6%
~20% within Area A · Mastery threshold: 70%
Critical: Planning process (PLAN-001), Housing (PLAN-003), Site planning per PRC 5-factor framework (PLAN-004). Housing finance added in v5.0.
ALE-PRAC
Architectural Practice & Jurisprudence
Area A · ~6%
~20% within Area A · Mastery threshold: 80%
Highest threshold (80%). RA 9266 and SPP fee structures high-frequency. CPD = 45 units/3 years (not 15 — legacy error corrected in v5.0). Quantity Surveying added in v5.0.
ALE-STRC
Structural Design
Area B · ~10.5%
~35% within Area B · Mastery threshold: 70%
Conceptual literacy, not calculation. Seismic Zone 2 (not 4) per NSCP 2015 — critical correction. Many is_computation_heavy flags here. Major 3D Lab opportunity for structural bay visualization.
ALE-MATL
Building Materials & Construction
Area B · ~9%
~30% within Area B · Mastery threshold: 75%
Critical: CHB dimensions, cement types, glass types, truss names. Philippine Bamboo Standards added. Use DAE visual memory — most architects have seen these materials in the field.
ALE-UTIL
Building Utilities (MEPF)
Area B · ~10.5%
~35% within Area B · Mastery threshold: 75%
Critical: Fire code travel distances (UTIL-001), plumbing fixture counts (UTIL-003). New DFU Reference Table subtopic (UTIL-001-04). High computation and 3D Lab flags. Communication & BAS systems expanded.
ALE-DSGN
Architectural Design & Site Planning
Area C · 40%
100% of Area C · Mastery threshold: 75%
Largest weight (40%) — single most important subject. Building code dimensional standards most tested. Expanded from 5 to 7 topics covering all 6 PRC building type categories. Strong 3D Lab alignment.
ALE-LAWS
Philippine Laws & Codes
Cross-Reference · 0%
Zero exam weight · Study subject only
Law questions distributed across Areas A, B, C. ALE-LAWS is the navigation layer. 66 verified legal URLs in v5.0. New ALE-LAWS-006 adds allied profession laws. is_cross_ref_only enforced by DB trigger.
PRC Area Weighting — Product Implication
Area C (ALE-DSGN) is 40% of the exam — a single subject. Area A and B are each 30%, split across 4 and 3 subjects respectively. The Readiness Score must use prc_area + area_weight_pct + subject_weight_within_area_pct to calculate weighted pass probability. A student at 70% accuracy on ALE-DSGN is far better positioned than a student at 80% on ALE-HIST. The current Readiness Score calculation must be updated after the import pipeline completes to use PRC area weights.

05 — New Opportunities

What the taxonomy unlocks
that wasn't possible before.

Beyond improving existing features, the new taxonomy fields enable entirely new product capabilities that were architecturally impossible without this data. These are not speculative — they have direct schema support and clear implementation paths.

1
PRC-Weighted Readiness Score — True Pass Probability

The current Readiness Score is a flat accuracy aggregate. With prc_area (A=30%, B=30%, C=40%) and subject_weight_within_area_pct, the score can now represent true ALE pass probability — weighting ALE-DSGN mastery 4× more heavily than ALE-HIST in the overall score calculation, which reflects the actual exam. No Philippine Licensure Exam prep platform has a pass-probability score calibrated to PRC's actual area weights.

Schema: prc_area + area_weight_pct + subject_weight_within_area_pct + mastery_criteria.threshold_pct → Readiness Score recalibration
2
Subject Floor Alert System — "You will fail even with high overall score"

The ALE requires a minimum 50% per subject (disciplines.subject_floor_pct = 50). A student at 75% overall can still fail the ALE if any single subject is below 50%. The Readiness Score currently has no sub-score floor alert. With mastery_criteria.threshold_pct per subject, the Analytics Dashboard can now show: "Warning: Your Structural Design score is 48%. You need at least 50% per subject to pass, regardless of your overall score." This is a genuinely life-changing alert — it prevents the most common surprise failure pattern.

Schema: disciplines.subject_floor_pct + mastery_criteria.mastery_threshold_accuracy_pct → sub-score alert system
3
Cognitive Progression Tracker — Bloom Level Advancement

Raw accuracy tells you how often a student gets questions right. bloom_level tells you what type of thinking they're demonstrating. A student at 90% accuracy on remember-level questions but 40% on apply-level questions understands the material but cannot use it — exactly the gap the ALE's hardest questions expose. The Analytics Dashboard can now show a Bloom progression bar per subject: "You've mastered recall and understanding. Your gap is application — you know what the code says but can't evaluate a scenario against it." This is a diagnostic layer no competitor can replicate without this taxonomy.

Schema: bloom_level + user_interactions.is_correct → per-level accuracy per subject
4
Prerequisite-Cascaded Remediation — "You failed this because you skipped that"

When taxonomy_prerequisites shows that ALE-UTIL-001-04 (DFU Reference Table) requires ALE-UTIL-001-02 (Fixture Units), and a student's heatmap shows UTIL-001-04 is Red, the system can now diagnose: "Your DFU calculation gap is rooted in your fixture unit fundamentals. Fix UTIL-001-02 first — it's the prerequisite." This is prerequisite-cascaded remediation, not just "study this weak node." The reverse lookup ("if UTIL-001-02 regresses, what else is at risk?") enables proactive cascade alerts. Most students who fail the ALE fail because they studied topics in isolation — prerequisite sequencing is the solution.

Schema: taxonomy_prerequisites (forward + reverse index) + user_node_mastery → cascade remediation queue
5
Computation Time Budget — Pacing Calibration per Node Type

Students failing the ALE due to time pressure often run out of time on computation sections. is_computation_heavy enables the Pacing Gauge to report per-category pacing: "You're spending 95 seconds per structural calculation question. At exam pace you need 72 seconds." The Endurance Cycle can prescribe computation-specific endurance sessions for students flagged as computation-slow. Camp Trail session time estimates use this flag to allocate more time for computation-heavy trail days. The existing avg_time_ms in user_interactions already captures this data — the flag makes it actionable.

Schema: is_computation_heavy + user_interactions.time_spent_ms → per-category pacing alerts
6
Legal Citation Widget — Live Law References in Wiki

taxonomy_sources is now populated with 66 verified URLs (all lawphil.net, officialgazette.gov.ph, and regulatory body sites). Every ALE-LAWS subtopic and code_provision node can now display a "Primary Laws" sidebar in wiki articles, showing clickable links to the actual legislation. This transforms wiki articles from self-contained summaries into connected legal references. When a student reads about BP 344's ramp specifications, they can click through to the actual 2024 Revised IRR on the NCDA website. This is a trust signal ("we cite the actual law") and a learning reinforcement ("the code says this, here's where").

Schema: taxonomy_sources.url + is_verified + source_type → wiki article legal citation sidebar
7
Question Bank Coverage Auditing — Automated Gap Detection

typical_question_formats defines what question types the ALE uses for each subtopic. The quiz engine can now automatically audit: "ALE-STRC-003-02 (Roof Truss Types) has typical_question_formats = ['mcq_recall', 'mcq_application'] but the question bank has only mcq_recall items — no mcq_application items exist for this subtopic." This automated audit runs on every question bank update, ensuring format coverage matches exam format reality. Without this flag, the question bank is assembled without knowing what the exam actually asks. With it, gap detection is automated and precise.

Schema: typical_question_formats + questions.application_context → automated coverage audit query
8
SME Authoring Speed — Structured Brief to Draft Article

The import pipeline Step 10 already implements auto-generation of wiki article stubs from wiki_items JSONB — converting heading/fact/definition/formula/code_provision/detail/exam_tip/cross_ref/warning items into structured Markdown. This means the 9 new v5.0 nodes (9 new subtopics across ALE-UTIL, ALE-LAWS) get draft articles automatically. For all 172 subtopics, SMEs inherit a structured brief instead of a blank page. Article authoring time drops significantly because the content structure is already determined by the taxonomy — SMEs expand, they don't invent from scratch. This is not a minor workflow improvement; it is the difference between sustainable content production and unsustainable ad-hoc authoring.

Schema: wiki_items typed JSONB → auto-scaffold Markdown on import pipeline Step 10
9
Exam Day Scheduling Intelligence — Day 1 vs Day 2 Preparation

disciplines.exam_day_1_subjects and exam_day_2_subjects are now stored in the database. The ALE splits across two days: Day 1 (History, Theory, Planning, Practice) and Day 2 (Utilities, Structural, Materials, Design). Students frequently over-prepare for Day 1 subjects and under-prepare for Day 2's highest-weight subject (ALE-DSGN at 40%). The system can now surface exam-date-aware pacing: "Your exam is in 14 days. Today is Day 1 preparation. You have 8 days before switching to Day 2 focus — your Day 2 Readiness Score is 52% vs Day 1 at 71%." Camp Trail exam simulation trail can now be split into Day 1 and Day 2 simulations.

Schema: disciplines.exam_day_1_subjects + exam_day_2_subjects → Day 1/Day 2 readiness split display
10
Allied Professions Awareness Module — Practice Boundary Navigation

ALE-LAWS-006 (Allied Professions & Emerging Practice Laws) is entirely new in v5.0. It covers interior design, landscape architecture, environmental planning, ease of doing business (building permit timelines), and safe spaces design implications — all of which define the scope boundaries of architectural practice in increasingly complex legal and professional contexts. A dedicated wiki section and quiz stream on "Scope of Practice & Professional Boundaries" becomes possible with this data. The ALE increasingly tests whether architects understand what they can and cannot do in relation to allied professions — and this is now mapped.

Schema: ALE-LAWS-006 (new topic) + 5 new subtopics + cross-refs to ALE-PRAC and ALE-PLAN → new content stream
06 — Gaps & Recommendations

What the taxonomy v5.0
still needs.

v5.0 is excellent but not complete in every dimension. Five gaps require attention before the new taxonomy data can be fully utilized across the product.

Gap 1 — Critical
Readiness Score Not PRC-Weighted Yet
The score recalibration using prc_area + area_weight_pct + subject_weight_within_area_pct is listed as a post-import application code update (Part 6 of the plan). This must be treated as a blocking requirement, not a nice-to-have. A Readiness Score that doesn't weight ALE-DSGN at 40% is systemically wrong — it underestimates the importance of the largest exam area. This update must ship with or immediately after the import pipeline completes.
Gap 2 — Critical
Prerequisite Graph Is Mostly Empty Placeholders
The v5.0 JSON acknowledges: "prerequisite_subtopic_ids arrays are empty [] in most subtopics — placeholders, populate via curriculum designer." Only 5 non-empty pairs exist in v5.0. The prerequisite cascade remediation (Opportunity #4 above) cannot be realized until this graph is populated. A structured prerequisite mapping sprint with the curriculum designer should be scheduled as a high-priority content task after migration 027 ships. The junction table infrastructure is ready — the SME work is not.
Gap 3 — High
Heatmap Query Must Exclude ALE-LAWS Before Import
The plan (Part 6) explicitly flags: "Heatmap query: add WHERE is_cross_ref_only = false AND deprecated_at IS NULL — before ALE-LAWS nodes are seeded (Step 2)." This application code update must be deployed before Step 2 of the import pipeline. If ALE-LAWS nodes are seeded before the heatmap query is updated, students will see law nodes in their mastery heatmap — which is wrong. This is a sequence-dependent requirement.
Gap 4 — High
Migration 028 Blocks Question Bank Scale
Migration 028 (session_questions junction table, replacing quiz_sessions.question_ids[]) is listed as priority "Before ~500 questions." The current question bank has 34 questions. This migration is needed before the question bank scales significantly. The session_questions junction table removes the array-based question storage limitation and enables proper question-session relationships at scale. Building the question bank aggressively while this migration is pending creates technical debt.
Gap 5 — Medium
wiki_items Types Need Wiki Renderer Support
The wiki_items typed objects (heading, fact, definition, formula, code_provision, detail, exam_tip, cross_ref, warning) are in the taxonomy and will be imported as structured JSONB. But the wiki article renderer must be updated to actually render them distinctively — warning types as highlighted callouts, exam_tips as pull quotes, formulas in monospace with visual treatment. Until the renderer supports the type system, all wiki_items render identically as flat text, losing the structural benefit entirely.
Gap 6 — Medium
three_d_lab_linked Flag Needs Systematic Audit
The three_d_lab_linked flag is set on "relevant subtopics across ALE-STRC, ALE-MATL, ALE-UTIL, ALE-DSGN" — but the v5.0 JSON shows many explicitly set to false for subtopics that arguably benefit from 3D visualization (e.g., Earthwork & Equipment, Specialized Works). A systematic review pass with the 3D Lab team should audit every false value against the question "Can a student understand this without seeing it?" — the research-validated filter for 3D Lab module need.
The Subject Floor Gap — Most Dangerous Product Omission
The ALE's 50% per-subject floor (disciplines.subject_floor_pct = 50) is now in the database. But there is no product feature that alerts a student when any individual subject score is approaching or below this threshold. A student with 78% overall but 47% in Structural Design will fail the ALE — and they might not know until results day. A sub-score alert system is not a nice-to-have. It prevents the most common surprise failure outcome. Build it as part of the Analytics Dashboard update after the import pipeline completes.
