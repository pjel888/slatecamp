Executive Summary: The current 3D Lab interface is functional but suffers from six systemic UX problems: information overload from unstructured side panels, no clear visual hierarchy between input controls and output metrics, missing viewport toolbars, inconsistent information density, no progressive disclosure, and a compliance scorecard that competes with the 3D viewport for attention. This document provides a research-backed redesign plan grounded in Blender, SketchUp, Figma, AutoCAD, and Cinema 4D UI patterns, combined with dashboard information architecture best practices.

Part I

UX Research & Audit

1. Current State Audit

1.1 Current Layout Analysis

The current 3D Lab uses a three-column layout with approximately 25% / 50% / 25% width distribution. The left panel contains inputs (lot parameters, zoning, FLAR, BHL, proposed building). The right panel contains outputs (layer visibility, KPI metrics, AMBF check, area closure, compliance scorecard, code reference).

1.2 Identified UX Problems

Problem 1
Information Overload — Left Panel

The left panel contains 19+ discrete controls and data sections in a single scrollable column: Presets (5 buttons), Lot Parameters (3 sliders), Lot Summary, Zoning Classification, Table VIII.1 Reference (6 rows), Floor Area Ratios (slider + 8 computed values), Building Height Limit (slider + 3 computed values), Firewall toggle, and Proposed Building (3 sliders).

Diagnosis: Approximately 3-4 screens of scrolling on 1080p. Users scroll past controls they've already set to reach controls they need. No grouping hierarchy. Violates Mayer's Coherence Principle and the Rams Standard.
Problem 2
Information Overload — Right Panel

The right panel contains 13+ output sections with no collapsible sections: Layer Visibility (8 toggles), TLA/AMBF/PSO/TOSL summary, BHL display, AMBF Three-Way Check (3 rows), Area Closure Identity, Compliance Scorecard (8+ items), Zone Legend, and Code Reference.

Diagnosis: Every piece of information is presented simultaneously at equal visual weight. The Compliance Scorecard alone is 400+ words of text competing with the 3D viewport.
Problem 3
Missing Viewport Toolbar

Industry-standard 3D applications universally provide viewport-attached toolbars for view manipulation, display modes, and measurement. The current Lab only has 5 view preset buttons at the bottom. Missing: zoom controls, display mode toggles, measurement tool, screenshot, fullscreen, grid toggle, axis gizmo.

Diagnosis: Critical viewport controls are either absent or buried in the panel scrolls. Breaks the universal pattern of "viewport controls attached to viewport."
Problem 4
Layer Visibility Is Misplaced

Layer toggles are at the top of the right panel — above metrics. In industry tools, layer controls are part of the viewport as overlay panels, not grouped with output data. They are view controls, not data displays.

Problem 5
No Progressive Disclosure

All information is visible simultaneously. No collapsible sections, no step-by-step guided mode, no tab-based organization, no summary vs. detail toggle. This contradicts our own Information Design Guide which mandates 4-layer progressive disclosure.

Problem 6
Compliance Scorecard Competes with Viewport

The scorecard occupies ~40% of the right panel's vertical space with 8+ pass/fail checks and code references. Red "FAIL" badges pull attention away from the 3D viewport where the student should be learning spatial relationships.

1.3 What's Working Well

Strengths
Solid Foundations to Build On

Color coding for pass/fail is clear and consistent. The AMBF Three-Way Check visualization is unique and pedagogically effective. Area Closure Identity stacked bar is an excellent spatial representation. Preset buttons provide quick scenario loading. The FLAR slider with zone range indicator is well-designed. BHL slider with computed vs. custom indicator works. Violation warnings in red text provide clear feedback.

2. Industry Research — 3D Software UI Patterns

After benchmarking Blender, Cinema 4D, 3DS Max, Maya, SketchUp, OnShape, Fusion 360, and Figma, seven universal patterns emerge:

Pattern 1
Viewport Gets Maximum Space

In every benchmarked app, the 3D viewport occupies 60-75% of total screen area. Side panels are narrow (200-300px) and collapsible. Our current viewport is only ~50%.

Pattern 2
Left = Inputs, Right = Outputs

Universal: left side contains active tools/inputs, right side contains passive properties/outputs. Our layout aligns but needs better internal organization.

Pattern 3
Viewport-Attached Controls

View manipulation is always attached to or overlaid on the viewport — never in a separate panel. Includes view presets, display modes, zoom, axis gizmos, grid toggles.

Pattern 4
Collapsible Sections with Icons

Properties panels in Blender, C4D, OnShape use icon-labeled collapsible sections. Each section has a small icon + label header. Users expand only what they need.

Pattern 5
Tab-Based Panel Organization

When a panel has too many sections, industry tools use tabs at the panel top. Blender uses icon tabs. C4D uses text tabs. Prevents the "infinite scroll" problem.

Pattern 6
Status Bar for Live Metrics

A persistent status bar at the viewport bottom shows real-time metrics: cursor position, selected element properties. Ideal for our TLA/AMBF/PSO/TOSL live summary.

Pattern 7
Floating Overlays for Context

Modern tools use floating overlays for contextual info — layer controls, measurements, quick-reference data. Can be opened/closed without affecting main layout.

Figma UI3 Lesson
Fixed Panels + Minimize UI

Figma learned floating panels slow power users down. Fixed but collapsible panels with a Minimize UI toggle gives the best of both worlds.

5. Input Panel Redesign (Left Panel)

Tab-Based Organization

Replace the single scrollable column with 3 tabs: 📐 Lot (Site Parameters), 🏗 Building (Proposed Building & Code Limits), and ⚙ Settings (View & Export). Each tab contains no more than 8 visible controls without scrolling.

Design Rationale: Tab-based organization reduces the perceived complexity from 19+ sections to ~6 visible sections per tab. It mirrors Blender's Properties panel approach — icon tabs that switch between contextual toolsets. Students only see what's relevant to their current task.

Collapsible Detail Sections

Within each tab, detail sections (FLAR Details, BHL Details) are collapsed by default with a chevron toggle. Primary information (slider + current value) is always visible; secondary computations (zone range, GFA allowable, TGFA comparison) are one click away.

7. Viewport Enhancements

7.1 Viewport Toolbar (Floating, Top-Left)

A floating toolbar with 6 icon buttons: Grid toggle, Dimension labels, X-ray mode, Layers dropdown, Screenshot, and Fullscreen. Positioned absolute top-4 left-4 with glass-morphism background (bg-black/60 backdrop-blur-sm).

7.2 KPI Bar (Viewport-Attached Bottom)

The 5 key metrics (TLA, AMBF, PSO, TOSL, BHL) are always visible at the bottom of the viewport, above the view mode buttons. These are the "vital signs" — they must never be scrolled past.

7.3 Axis Gizmo

A 3D axis orientation gizmo in the top-right corner using drei's GizmoHelper. Click on axis face to snap to orthographic view. Provides spatial orientation feedback critical for learning setback relationships.

7.4 Layer Controls Overlay

Layer visibility toggles move from the right panel to a floating overlay triggered by the Layers button in the viewport toolbar. Anchored below the toolbar, glass-morphism background, closes on click outside. Includes "Show All" / "Hide All" quick actions.

Part III

UI Component Specifications

9. Component Design Standards

Section Header Component

Chevron (12px, rotates 90° on collapse) + Title (font-mono text-[9px] uppercase tracking-widest) + Optional badge (right-aligned, status colors). Divider 1px below. Collapse animation via max-height transition at 200ms.

KPI Card Component

Compact metric chip: 56px min-width, 48px height. Label in font-mono text-[8px] uppercase, value in font-mono text-lg font-bold tabular-nums. Transparent background on KPI bar, bg-muted/50 in panels. Red text when violating.

Pass/Fail Badge

Subtle tint backgrounds — never solid fills. PASS: bg-green-50 text-green-800 border-green-200. FAIL: bg-red-50 text-red-800 border-red-200. Mono font, 9px, 4px radius.

Violation Banner

Viewport overlay, bottom-left above KPI bar. bg-red-50/90 backdrop-blur-sm border border-red-200. Solid red circle icon. Never auto-dismisses — stays until violation is resolved.

Unified Slider Standard

Every slider follows: Label (mono, uppercase, 9px) + Value (mono, bold, red if violating) on the same row, slider track below (4px, cobalt fill), optional context line underneath for violation warnings or zone references. Thumb: 16px circle, white fill, cobalt border.
