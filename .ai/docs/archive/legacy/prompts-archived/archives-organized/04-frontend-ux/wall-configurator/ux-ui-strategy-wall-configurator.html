User Research & Cognitive Context

Primary Persona

Estimator / Junior QS
Philippine Construction Project · On-site or Office
Device context
Desktop or tablet. Mid-range hardware, intermittent internet.
Task context
Material takeoff for a wall scope before issuing a purchase request.
Time pressure
Estimating is a supporting task. Needs answers in minutes, not a learning curve.

Pain Points: Disjointed vs. Unified

Pain Point Current State (Separate Calculators) Unified Resolution
Double-entry of geometry L × H entered separately in CHB, paint, and plaster tools One geometry block drives all downstream layers
Lost opening deduction User manually subtracts door/window area — error-prone Opening deduction computed once, applied to all finish layers
Side ambiguity Paint calculator has no side context; user guesses whether to double Explicit 1/2-sides toggle with live area preview drives all side-dependent layers
Inconsistent waste factors User applies different or no waste to each material Sensible defaults per material; editable without being hidden
No procurement output Outputs raw liters or kg with no packaging rounding Three-tier output: theoretical → adjusted → commercial procurement
Mental re-entry fatigue Switching tools loses context; user re-reads spec sheets each time Full sequence visible in one scrollable layer stack

Cognitive Load Reduction Priorities

Priority 1 — Sequence is not negotiable. The 7-step flow maps to the physical construction sequence: core → openings → sides → treatment → finish → output. Users who understand construction will recognize this immediately. Do not reorder steps.
Priority 2 — Gross vs. net must be made visible. The single highest risk of error is applying finish to gross area when openings exist. Both numbers must appear simultaneously in a persistent summary bar, explicitly labelled throughout.
Priority 3 — Results must be self-explanatory. The BOM must be readable by a foreman with no software training. Labels use trade language: "CHB pcs", "40-kg bags", "16 L pails" — not variable names or codes.

Information Architecture & User Flow

Screen Model

The configurator operates as a single-page progressive form — no full page navigations. Steps are accordion panels: completed steps collapse to a summary chip (editable on click). The persistent area bar is always in viewport.

1
Select Core Type
CHB · Drywall · Existing Finished Wall. Choice seeds the default layer stack. Finishing sequence preview shown on each card.
Required — unlocks Step 2
2
Enter Wall Geometry
Length (m) · Height (m) · Wall count. Gross area computed and displayed live in area bar.
Required — unlocks Steps 3 and 4
3
Enter Openings
Dynamic row list: label · width · height · qty per opening. Opening area deducted live. Net area updates in persistent bar.
Optional — can skip; defaults to 0 deductions
4
Choose Sides
Segmented control: [1 Side] or [Both Sides]. Finish area = net area × sides, shown live in bar. Explanation sentence updates in real time.
Required — unlocks Step 5
5
Select Treatment Layers
Layer cards seeded from core type. Each: toggle ON/OFF + wastage % input. CHB: plaster, skim. Drywall: board, tape, compound. Existing: skim.
Optional — sensible defaults active
6
Select Finish Layers
Primer toggle + coat count. Topcoat toggle + coat count stepper + coverage rate (default 7 sqm/L). BOM preview auto-updates as values change.
Optional — sensible defaults active
7
View Bill of Materials
Three-tier table + area summary card + assumptions footer. Always auto-updates when any earlier step changes. Print and export actions.
Always available once Step 2 is complete

Collapsed Step Chip Pattern

Once a step is completed, it collapses to a one-line summary chip showing its key values. Example:

✓ Step 2 — Geometry    5.0 m × 3.0 m × 2 walls = 30.00 sqm    [Edit]
✓ Step 3 — Openings    2 doors + 1 window = 4.41 sqm deducted    [Edit]

Clicking "Edit" re-expands the panel inline. No navigation away from page.

Layer Stack — Design Rules

RuleSpecification
Layer ordering is fixed CHB → Plaster → Skim → Primer → Topcoat. Order communicates construction dependency. Designer must not allow reordering.
Disabled layers stay visible OFF layers remain in the DOM at reduced opacity. They are not removed. Allows user to opt back in without confusion.
Basis badge required on every row "AREA / SIDE", "PIECE", "PANEL / SIDE", or "LINEAR". DM Mono uppercase 8px. Explains the calculation basis to the estimator.
Wastage is always editable Never hidden behind an "advanced" toggle. Estimators adjust waste based on site conditions. 5%/10% defaults are starting points, not locked values.
Topcoat coat count stepper Inline [−] N [+] control. Min 1, no max. Updates BOM immediately on change.

Bill of Materials: Results Visualization

Three-Tier Output Logic

TierColumn LabelPurposeUser Action
1. Theoretical Formula Qty Raw formula output at 0% waste — reference only None — not for ordering
2. Adjusted + Wastage Formula × (1 + waste factor) — engineering estimate Cross-check against experience
3. Procurement ORDER QTY ▲ Adjusted qty rounded to commercial package sizes This is what to write on the purchase request
The ORDER QTY column is primary. It must be the rightmost, largest, and most visually prominent. Theoretical is reference data — present but subdued. The column header carries a ▲ marker to signal primacy.

Usability Testing Protocol

Test Setup

ParameterSpecification
Participants5 minimum per round. Site estimators, junior engineers, or draftspeople with material takeoff exposure. Philippine construction context preferred.
FormatModerated task-based session, 30–45 minutes. Remote acceptable (screen share + video).
DeviceDesktop or tablet (priority hardware). One mobile session to flag breakpoints.
Prototype fidelityMedium-fidelity interactive. All three BOM tiers must show functional values — not placeholder data.

Three Test Scenarios

Scenario 1
Opening Deduction Awareness

Objective: Validate users understand gross vs. net area and that opening deductions happen automatically.

"You are estimating materials for a CHB partition wall: 4 meters long, 3 meters high, with one door (0.90 m × 2.10 m) and one window (1.20 m × 1.20 m). Set this up in the configurator and identify the area that will be used to calculate plaster quantities."
Success Criteria (✓)
  • User enters wall geometry in Step 2 without manually pre-subtracting opening area.
  • User adds openings in Step 3 and observes net area update in persistent summary bar.
  • When asked "What area is used for plaster?" user answers with net area (not gross).
Failure Signals (⚠)
  • User attempts to pre-subtract openings from the length/height input before entry.
  • User cannot locate the net area value after completing Step 3.
  • User believes gross area is used for plaster once openings are entered.
Probe Question

"Where in the screen would you look to confirm how much area the plaster calculation is based on?"

Scenario 2
Side Selection Ambiguity

Objective: Validate users understand the 1-side / 2-sides distinction and can correctly apply it without guidance.

"You're finishing both faces of a drywall partition between two offices — gypsum boards on both sides, with primer and paint on both sides. Configure this correctly in the configurator."
Success Criteria (✓)
  • User selects "Both Sides" in Step 4 without prompting.
  • User can read the updated finish area from the persistent bar (net area × 2).
  • User can articulate why board count and paint quantities are roughly double the one-side scenario.
Failure Signals (⚠)
  • User selects "1 Side" and does not notice or question the output.
  • User selects "Both Sides" but cannot find where the doubled finish area is shown.
  • User doubles the wall count input instead of using the sides toggle.
Probe Question

"If you had set this to one side instead, what quantity would change in the bill of materials — and by how much?"

Scenario 3
Procurement Tier Interpretation

Objective: Validate that the three-tier BOM is correctly interpreted — specifically that ORDER QTY, not formula or wastage, is what the user takes to a supplier.

"You've completed the configuration. Your site foreman is calling you right now asking: 'How many bags of cement do I need to order for plastering?' Look at the results and give them a number."
Success Criteria (✓)
  • User reads from the "ORDER QTY" column — not Formula Qty or +Wastage.
  • User reads the rounded, whole-unit value (e.g., "6 bags"), not a decimal.
  • User does not perform any additional mental arithmetic to arrive at the answer.
Failure Signals (⚠)
  • User reads the decimal adjusted quantity and rounds manually ("about 5 and a half").
  • User reads the theoretical (no-waste) quantity.
  • User cannot identify which of the three columns to use without asking the facilitator.
Probe Question

"There are three numbers for cement in this table. Can you tell me in your own words what each one means, and which one you'd actually use?"

Pass/Fail Thresholds for Design Release

CriterionThreshold
Scenario 1 — Net area identified correctly without prompting ≥ 4 of 5 participants (80%)
Scenario 2 — Both sides applied correctly without guidance ≥ 4 of 5 participants (80%)
Scenario 3 — ORDER QTY column used for purchase request 5 of 5 participants (100%)
Zero participants believe finish applies to gross area when openings are present 0 failures tolerated
If any threshold is not met, the failing component is redesigned and re-tested before the feature is released. No exceptions.
