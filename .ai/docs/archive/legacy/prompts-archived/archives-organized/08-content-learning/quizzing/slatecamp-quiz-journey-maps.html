Part 1 — Research Foundation

Executive Summary

This document maps every user interaction with the SlateCamp quiz engine from the moment intent forms ("I want to study") through session completion, review, and the behavioral loop that brings users back. It exists so that any developer, designer, or AI system can understand not just what to build, but why — the psychological states, decision points, and behavioral expectations that justify every feature.

The core insight: A quiz session is not a single interaction — it is a 7-phase emotional arc that begins before the first question loads and continues after the last answer is reviewed. Each phase has distinct user psychology, cognitive load, and design requirements. Missing any phase creates a fracture in the learning experience.

User Personas & Mental Models

Every journey map in this document is viewed through these four lenses. Each persona enters a quiz with different emotional baggage, cognitive readiness, and outcome expectations.

Persona A

The Anxious First-Taker

Age 22–26 · Fresh grad · 3–5 hrs/day studying with no measurement

Core fear: "What if I fail on the first try?"
Mental model: More hours = more prepared (wrong — no signal)
Quiz behavior: Starts with Camp Mode because trail tells them what to do. Reads every rationale carefully. Feels validated by correct answers, devastated by wrong ones. Needs the intro screen to reduce anxiety before first question.
Expected outcome: Wants to feel "I learned something today" — score matters less than sense of progress.
Risk: Abandons session if first 3 questions are too hard. Catastrophizes a low score.
Persona B

The Retaker

Age 24–30 · Failed ALE 1+ times · Emotionally scarred

Core fear: "I studied hard last time and it didn't work"
Mental model: Distrusts their own readiness instincts
Quiz behavior: Gravitates to Focused Review and Storm Mode. Skips intros — wants to get into questions fast. Reads rationales on wrong answers obsessively. Bookmarks questions they're unsure about.
Expected outcome: Wants concrete evidence of improvement vs. last attempt.
Risk: Triggered by low scores — may abandon platform entirely. Needs growth framing desperately.
Persona C

The Undergrad Prepper

Age 19–23 · 3rd-4th year student · Low urgency, high curiosity

Core fear: None (yet) — studying proactively
Mental model: "I want to be ahead of everyone"
Quiz behavior: Uses Chill Mode and Subject Mode. Short sessions (10–15 questions). Skips rationales when correct. May ghost for weeks then return.
Expected outcome: Curiosity satisfaction. Discovery. "Oh, I didn't know that."
Risk: Low engagement depth. Won't pay. May never complete a full session.
Persona D

The Working Professional

Age 28–38 · 2–8 years since graduation · 30–60 min/day max

Core fear: "I've forgotten everything"
Mental model: Time efficiency is everything
Quiz behavior: Uses Camp Mode daily during commute. Extended Practice on weekends. Values the intro screen's time estimate. Will abandon if session feels longer than promised. Power user of review mode — reviews missed questions on lunch break.
Expected outcome: Maximum learning per minute. Visible daily progress.
Risk: Churn if sessions take longer than estimated. Pays gladly if shown value.

The Core Behavioral Loop

Every quiz session exists within this larger behavioral cycle. Understanding the loop explains why the intro and summary screens are not optional — they are the connective tissue between sessions.

User decides to study. Triggered by: notification, guilt, habit, exam proximity.

2. Orientation

→
⚡
3. Engagement

Active quizzing. Flow state. Questions answered. Learning happens through retrieval.

→
📊

Summary screen transforms raw score into direction. "What did I learn? Where next?"

→
🔁
5. Re-entry

User returns. Next session begins. Readiness Score updates. Loop continues.

Why the intro and summary are critical: Without the intro, users enter quizzes anxious and disoriented — "How many questions? How long? What topic?" This anxiety bleeds into performance. Without the summary, the session feels like it evaporated — no closure, no direction, no reason to return. Both screens are behavioral bridges that connect one session to the next and convert a scattered experience into a compounding mastery loop.

Quiz Engine Design Principles

Seven non-negotiable rules that govern every design decision in the quiz engine. Any feature, screen, or interaction that violates these is wrong.

Principle 1

No Layout Shift — Ever

The two-column layout (question left, options right) is immutable on desktop/tablet. The brain builds spatial memory. We never break that contract.

Principle 2

Orient Before Engage

Every session starts with an intro screen that answers: What topic? How many? How long? How hard? No question loads until the student is ready.

Principle 3

Close With Direction

Every session ends with a summary that transforms the score into a next action. Never a dead end. Never "just a number."

Principle 4

No Red, No Punishment

Wrong answers use amber/warm tones with growth language. Correct answers use Cobalt Blue. Red is banned from all quiz feedback.

Principle 5

One Shell, Config-Driven

All 8 modes share one quiz engine. Differences are config flags (timer, feedback timing, navigation), not separate UI codebases.

Principle 6

Review Is Learning

The post-quiz review is not a scoreboard — it's a teaching session. Every wrong answer includes why-you-chose-wrong + why-correct-is-correct rationale.

Phase 1

Intent & Entry

Steps 1.1 → 1.5

The user forms intent to study and navigates to a quiz session. This phase exists BEFORE any quiz UI loads. The emotional state here determines whether the user follows through or abandons.

1.1
Intent Forms
User decides "I should study now"

Trigger sources: Push notification ("Day 14 is ready"), self-initiated (opens app), exam anxiety spike (saw a social media post about ALE results), routine habit (daily 7pm study slot), boredom/procrastination.

Emotional state Mixed. Anxious-to-motivated range. Retakers feel dread. First-takers feel obligation. Professionals feel time pressure.
Cognitive load Low. No quiz content yet. Mind is switching from previous activity into "study mode."
User action Opens SlateCamp app or navigates to web dashboard.
Drop-off risk HIGH if app opens to a blank or confusing dashboard. First impression must immediately show a clear "Start here" action.
1.2
Dashboard Assessment
User scans dashboard for what to do next (≤5 seconds)

What the user is looking for: "What should I study today?" — the answer must be immediately visible. Camp Trail users see "Start Day 14." Non-trail users see recent mode or mode selector. Unfinished session users see "Resume Session" banner.

Emotional state Scanning. Looking for a clear signal. Decision fatigue if options are unclear.
Cognitive load Low-Medium. Processing dashboard info. Must find primary CTA in ≤5 seconds.
User action Eyes scan top-to-bottom. Reads Readiness Score. Reads Camp Trail status. Taps primary CTA.
Drop-off risk MEDIUM if dashboard shows 5+ equal-weight actions. Must have ONE clear primary action.
1.3
Mode Selection (if needed)
User chooses their exam mode OR mode is pre-selected

Pre-selected paths (no choice needed): Camp Trail → Camp Mode auto-selected. Heatmap node tap → Subject/Focused auto-selected. "Practice Missed Qs" CTA → Focused Review auto-selected. Push notification deep link → mode pre-configured.
Choice required: Mode Selector grid opens. 8 cards in 2 groups ("Learning" and "Exam" and "Custom"). User taps one card.

Emotional state Confident if path is pre-selected (relief: "the system knows what I need"). Mildly overwhelmed if choosing from 8 modes (Hick's Law — 8 choices = ~3 sec decision time).
Cognitive load Low for pre-selected. Medium for mode choice. Grouping into Learning/Exam/Custom reduces perceived complexity.
User action Pre-selected: automatic progression. Choice: scan cards, read 1-line descriptions, tap preferred mode.
Drop-off risk LOW for pre-selected (no choice paralysis). MEDIUM for mode selector if descriptions are unclear or modes feel overlapping. Users must instantly understand the difference between modes.
1.4
Expected User Behavior by Persona
How each persona navigates entry differently
Anxious First-Taker: Follows Camp Trail. Taps "Start Day X." Doesn't explore other modes. Needs the pre-selected path or they'll freeze.
Retaker: Goes to Mode Selector or Heatmap. Picks Focused Review or Storm Mode. Knows exactly what they want. Skips through quickly.
Undergrad: Wanders. May browse modes before choosing Chill Mode. Low urgency. May close app before starting.
Professional: Follows Camp Trail. Values efficiency. Checks time estimate on intro screen. Starts only if it fits their available window.
Phase 2

Session Intro ("The Briefing")

Steps 2.1 → 2.6
Why this phase exists: Research shows that students who know what to expect before a test perform better and report lower anxiety (Cassady & Johnson, 2002). The intro screen is not bureaucracy — it is a cognitive warm-up that transitions the brain from passive to active learning mode. It answers the 5 questions every student unconsciously asks: What am I about to do? How many questions? How long? What topic? Can I handle this?
2.1
Intro Screen 1: Session Briefing Card
The "here's what you're about to do" screen · All modes

Full-screen slide. Centered content. Shows: mode icon, mode name, topic (if known), question count (adjustable stepper), estimated time, difficulty level, feedback type. This is a breathing room — the last moment of calm before the quiz begins.

Emotional state Anticipation. "Okay, this is manageable." The time estimate is the most reassuring element — "only 15 minutes" transforms dread into commitment.
Cognitive load Low. One screen, one purpose. User only needs to read and confirm or adjust count.
User action Reads session summary → optionally adjusts question count via ± stepper → taps "Begin Session →"
Drop-off risk LOW for Camp/Chill (one slide, fast). MEDIUM if count feels too high (default 200 for Full Exam could intimidate). Time estimate is the key anxiety reducer.

Screen elements (complete inventory)

Header: ← Back button (returns to previous screen) · Mode badge (DM Mono uppercase)
Center block: Mode icon (48×48px) · Mode name (H3) · Topic (if pre-selected) · Summary line: "[20] questions · Adaptive · Instant feedback" · Question count stepper (±5 step, min 5, max varies) · Time estimate ("~15 min") calculated at 45s/q for learning, 72s/q for exam
Footer: "Begin Session →" primary CTA (full-width, 48px) · "Change mode" ghost link
Conditional elements: Camp Mode shows "Day 14" prominently · Full Exam Sim shows environmental checklist · Storm Mode shows "No feedback during exam" warning
2.2
Intro Screen 2: Topic Picker (Conditional)
Choose what to study · Subject Mode, Focused Review, Custom only

Shown only when the user needs to select topics. Displays 6 ALE subjects with mastery indicators (% score + color dot). Tapping a subject expands topic-level chips. In Focused Review, weakest topics are pre-selected by the Blindspot Protocol algorithm.

Emotional state Engaged decision-making. Seeing mastery %s creates micro-motivation ("I need to work on Utilities — it's only 31%").
Cognitive load Medium. Processing 6 subjects × mastery data. Mitigated by pre-selection (Focused Review) and grouping.
User action Scans subjects → taps one (Subject Mode) or multiple (Custom) → optionally drills into topic chips → taps "Continue with [selection] →"
Drop-off risk LOW. Users who reach this slide are committed. Risk: paralysis if too many topic chips visible. Max 8 visible per subject, "Show all" for rest.
2.3
Intro Screen 3: Advanced Config (Conditional)
Full control panel · Custom Session only

Toggle switches for: instant feedback, timer, free navigation, question palette. Difficulty selector (Easy/Medium/Hard/Mixed). Preset shortcuts ("Use Storm settings" / "Use Camp settings") for power users. This screen is ONLY for Custom Mode.

Emotional state Empowered. "I control this." Power users feel satisfied. New users may feel overwhelmed → presets solve this.
Cognitive load High. 6+ decisions. Mitigated by good defaults and preset shortcuts.
User action Scans defaults → adjusts toggles → selects difficulty → taps "Begin Custom Session →"
Drop-off risk LOW (power users chose Custom intentionally). Risk: user creates a configuration that produces a bad experience (e.g., Hard + no feedback + 100 questions → frustration). Consider warning for extreme configs.
2.4
Loading Transition (500ms)
Emotional buffer between intro and first question

After tapping "Begin Session," a brief loading state appears: skeleton outline of the two-column layout with the progress bar at 0%. This is NOT a spinner — it's a preview of the quiz environment the brain is about to enter. The first question fades in over 300ms. This transition gives the prefrontal cortex a moment to shift into "question-answering mode."

Emotional state Micro-anticipation. "Here we go." The skeleton preview makes the transition feel smooth, not jarring.
Cognitive load Near zero. Brain is transitioning. No decisions required.
User action Waits. No interaction required. Eyes settle on the emerging two-column layout.
Drop-off risk ZERO if under 1 second. HIGH if loading takes >3 seconds (connection issue). Show skeleton, not blank white.

Phase 3

Active Quizzing ("The Flow")

Steps 3.1 → 3.8

The core interaction loop. Every question follows this exact sequence. The two-column layout is immutable. This phase has the highest cognitive load and the most opportunities for flow state — or flow destruction.

3.1
Question Loads (Left Column)
User reads the question stem

Left column renders: topic breadcrumb → question number → question stem text → image/diagram (if applicable). Right column renders: "Select your answer" label → four answer options (A–D) in idle state. User's eyes go to the LEFT column first, read the question, then move RIGHT to the options. This left-to-right reading flow is natural and must never be disrupted.

Emotional state Focused. "Let me understand this question." Curiosity if topic is interesting. Anxiety if topic is a known weakness.
Cognitive load HIGH. Processing the question stem is the most cognitively demanding moment. All extraneous elements must be minimized.
User action Reads question stem top-to-bottom. If image present: studies image. May re-read stem. Eyes then move to right column.
Drop-off risk LOW per question. Risk: question stem is too long (>4 sentences) causing cognitive overload. Risk: image and text compete for attention (Split-Attention Effect — mitigated by placing image below stem, not beside it).
3.2
Answer Selection (Right Column)
User evaluates options and selects one

User scans A→D vertically. Elimination process: crosses out obviously wrong answers mentally (exam modes: strikethrough gesture available). Narrows to 2 options. Selects one. The selected option changes to Cobalt Light background with Cobalt border — providing immediate visual confirmation "I picked this one." Submit button transitions from disabled (grey) to active (Cobalt).

Emotional state Retrieval effort. If confident: satisfaction. If uncertain: anxiety. This is where "desirable difficulty" lives — slight struggle = learning.
Cognitive load PEAK. Comparing 4 options against question stem. Working memory at capacity. Eyes dart between left (question) and right (options).
User action Scans options → eliminates 1–2 → selects answer → option highlights → submit button activates.
Drop-off risk VERY LOW. User is engaged. Risk: accidental selection of wrong option (mitigated by requiring explicit Submit tap — selection ≠ submission). Risk: all 4 options look plausible → frustration → wild guess.
3.3
Confidence Rating (Left Column, Learning Modes)
User rates their certainty: Guessing / Somewhat sure / Very sure

Only in modes with confidence rating enabled (Camp, Subject, Focused). Located at the bottom of the left column, below the question. Three horizontal pills. Optional — user can skip by going directly to Submit. Purpose: builds metacognitive awareness ("I thought I knew this, but I was guessing") and feeds the adaptive difficulty algorithm.

Emotional state Self-reflection. Brief metacognitive moment. "Do I actually know this or am I bluffing?"
Cognitive load LOW. Simple 3-way choice. Doesn't interfere with answer recall.
User action Taps one of three confidence pills → then taps Submit on the right column.
Drop-off risk ZERO. Risk: users skip confidence every time (acceptable — it's optional). Risk: users feel judged by the rating (mitigate with neutral language, no consequences shown).
3.4
Submit Answer
User taps "Submit Answer" on the right column

200ms processing delay (prevents double-tap). Then branching based on mode config:

Immediate Feedback Path (Camp, Chill, Subject, Focused, Extended):
Right column transitions: options become annotated (correct highlighted in Cobalt, user's wrong answer highlighted in Amber) → feedback rationale panel slides in below options → "Next" button appears after gated delay (3s Camp, 4s Focused, 2s Extended, 0s Chill). Left column: unchanged. Question stays visible for reference.
Deferred Feedback Path (Storm, Full Exam):
Brief toast: "Answer recorded ✓" (1.5s, auto-dismiss). No option annotation. No rationale. Auto-advances to next question. Or user navigates freely via palette.
3.5
Read Feedback (Immediate Mode Only)
User reads why their answer was right or wrong

Correct answer: Cobalt Light bg panel. "Correct — nice work." + 40–80 word explanation + Wiki link. User feels validated. Reads explanation to reinforce.
Wrong answer: Amber bg panel. "Not quite — let's look at this." + "Your answer" vs "Correct answer" comparison + wrong-answer-specific explanation ("You chose X — this is actually for non-habitable rooms...") + Wiki link. User learns from the specific error, not just the correct answer.

Emotional state Correct: brief dopamine hit, reinforcement. Wrong: micro-disappointment → curiosity (if rationale is well-written) OR frustration (if rationale is unclear). The quality of the rationale determines whether wrong answers feel like learning or punishment.
Cognitive load MEDIUM. Processing new information. Two-column layout helps: question on left for reference, feedback on right for learning.
User action Reads feedback panel (3–10 seconds). May tap Wiki link for deeper dive (opens in new view, returns to quiz). Waits for / taps "Next Question →".
Drop-off risk LOW. Risk: user skips rationale entirely (gated Next button mitigates — forces 2–4 sec reading). Risk: rationale is too long (>100 words) → user glazes over. Keep rationales concise with expandable "Learn more."
3.6
Advance to Next Question
User taps "Next Question →" or auto-advances

150ms opacity crossfade. Left column loads new question. Right column resets to fresh options. Progress bar advances. Fraction updates. The layout does not change. Only the content changes. This is the spatial consistency promise — question 8 looks identical to question 1 structurally.

3.7
Fatigue Intervention Points
Micro-breaks and milestone markers at predictable intervals

At configurable intervals (25 Qs for Storm, 30 Qs for Extended, 50 Qs for Full Exam): a gentle card slides up from the bottom of the screen. "You've completed 25 questions. Quick stretch?" with a 30-second rest timer and "Continue" button. The card overlays BOTH columns without replacing them — the quiz state is preserved underneath.

Emotional state Relief. Permission to rest. "Halfway there" creates a second-wind effect if progress framing is used.
Cognitive load NEAR ZERO during break. Brain recovery. This is when working memory consolidates recent learning.
User action Reads milestone message. Optionally rests. Taps "Continue" to resume. Or dismisses immediately.
Drop-off risk MEDIUM. Break can become an exit point if user checks phone/notifications. Keep break card motivational, not interruptive. Never block the quiz — user can dismiss instantly.
3.8
Loop: Steps 3.1–3.6 Repeat for Every Question
Same spatial layout, same interaction pattern, every single time

The entire active quizzing phase is this loop repeated N times (where N = question count). The consistency of the loop is what enables flow state. Any deviation (layout change, unexpected modal, jarring animation) breaks flow and is felt as cognitive friction.

Phase 4

Submission ("The Finish Line")

Steps 4.1 → 4.4

The transition from active answering to results. This is an emotionally delicate moment — the user is simultaneously relieved (it's over), anxious (how did I do?), and tired (cognitive fatigue). The design must honor all three states.

4.1
Last Question Signal
The "Next" button changes to "Finish Session →" or "Review & Submit →"

Learning modes: After last question's feedback, button text becomes "Finish Session →" in Camp Orange accent. No pre-submission review needed — user already saw all feedback.
Exam modes: Button becomes "Review & Submit →". Opens the pre-submission review screen showing question grid with answered/unanswered/flagged status.

4.2
Pre-Submission Review (Exam Modes Only)
Full-screen question grid for final check

Shows all questions in a numbered grid (10 columns). Each cell is color-coded: Cobalt = answered, Grey outline = unanswered, Orange = flagged. Summary stats: "48 answered · 2 unanswered · 3 flagged." Filter pills: "Show unanswered" / "Show flagged." Tapping a cell jumps back to that question in the quiz shell. Two CTAs: "Submit Exam" (primary) + "Keep Reviewing" (secondary).

Emotional state Scrutiny + anxiety. "Did I miss anything?" Seeing 2 unanswered questions creates urgency. Seeing all cells filled creates relief.
Cognitive load LOW-MEDIUM. Scanning a grid, not processing new questions. Pattern recognition ("any grey cells?").
User action Scans grid for unanswered/flagged → jumps to fix any → returns → taps "Submit Exam"
Drop-off risk VERY LOW. User has invested 1–4 hours. They will submit.
4.3
Confirmation Modal
"Are you sure?" — intentional friction before finality

Learning modes: "End this session? Your progress is saved." → "End & See Results" (primary) + "Keep Going" (ghost).
Exam modes: "Submit your exam? This cannot be undone." + if Full Exam: "Results will be available in 24 hours." → "Submit Exam" (Camp Orange, destructive positioning) + "Go Back" (primary visual weight — we nudge toward continuing, not quitting).

4.4
Processing Buffer (500–800ms)
Emotional decompression between exam and results

Full-screen overlay with SlateCamp mark and "Calculating your results..." text. This is NOT a loading screen — it's a deliberate emotional buffer. The brain needs a moment to shift from "answering mode" to "receiving mode." Score count-up animation begins immediately after this buffer. For Full Exam Sim: buffer transitions to "Your Proof Simulation has been submitted" confirmation (no score).

Phase 5

Results Summary ("The Scoreboard")

Steps 5.1 → 5.6
Critical UX moment: This is the most emotionally vulnerable screen in the product. The user just expended significant cognitive effort and is now receiving judgment. A poorly designed results screen can undo all the positive learning from the session. The score must be framed as information, not verdict.
5.1
Score Reveal (Count-Up Animation)
The headline number: "17 / 20" counting up over 1.5 seconds

Score displays as fraction (17/20) with percentage secondary (85%). Count-up animation builds anticipation. DM Mono, 56px, Cobalt. Below: pass/fail framing — ≥70% shows "Passing" in Signal Green text. 40–69% shows "Building" in neutral charcoal. <40% shows "Needs review" in neutral. NEVER red text for any score.

Emotional state PEAK EMOTIONAL MOMENT. Count-up creates suspense → resolution. High score: joy, validation. Low score: disappointment. Growth delta ("▲ +8%") shifts focus from absolute to relative progress.
Cognitive load LOW. Processing one number. But emotional load is HIGH.
User action Watches count-up. Reads score. Reads growth delta. Scrolls down for breakdown.
Drop-off risk HIGH for low scorers. A low score with no context or direction feels like a dead end. MUST pair with growth delta and immediate next action. "You improved +3 from last time" is more important than "55%."
5.2
Performance Breakdown
Score by subject/topic with progress bars

Cream background card showing each subject covered: name, fraction (8/10), and Cobalt progress bar. Sorted weakest-first (blindspot-first ordering). For Extended/Storm/Full Exam: shows accuracy over time chart (25-question blocks) to surface stamina degradation ("Your accuracy dropped from 90% to 65% in the final quarter — that's a stamina signal").

5.3
Readiness Score Impact
"Your Readiness Score: 72 (▲ +2)"

Cobalt Light card showing current Readiness Score + delta from this session. This connects the individual quiz to the larger mastery trajectory. Pro users see the full trajectory. Free users see this once then hit paywall on subsequent sessions. Chill Mode: Readiness Score NOT shown (casual mode doesn't affect mastery metrics).

5.4
Action CTAs (The Bridge to Next Session)
Three tiered actions: Review → Practice Missed → Dashboard

Primary: "Review Your Answers" (Cobalt, full-width) — enters Phase 6 Review Mode.
Secondary: "Practice Missed Questions (3)" (outlined) — auto-creates a Focused Review with missed Qs. Shows count.
Tertiary: "Back to Dashboard" (ghost link).
Camp Mode addition: "Day 15 Unlocked: Building Laws" preview card + "Start Day 15 →" CTA for momentum.

Emotional state Direction-seeking. "What now?" The CTA hierarchy guides this: most learning-valuable action (Review) is most prominent.
Cognitive load LOW. Three clear options, hierarchically ordered. No decision fatigue.
User action ~60% tap "Review Your Answers." ~25% tap "Practice Missed." ~15% go to Dashboard. (Target metrics.)
Drop-off risk MEDIUM. This is the second most common exit point after the session itself. Users who skip review lose 50% of the learning value. Review CTA must be compelling, not just available.
5.5
Expected Behavior by Persona at Results
Anxious First-Taker: Stares at score for 5+ seconds. Reads every breakdown line. If passing: huge relief, may screenshot. If below 70%: anxiety spike — growth delta and "every camper starts somewhere" messaging critical.
Retaker: Immediately compares to last attempt. Growth delta is the most important element. Taps "Review Your Answers" to obsessively study wrong answers. Will spend 2–3× longer in review than the quiz itself.
Undergrad: Glances at score, notes "not bad" or "oof." Rarely reviews. Goes to Dashboard. May not return for days. Score is curiosity-satisfying but not motivating enough to drive review behavior.
Professional: Checks breakdown for time-efficient insights. "Where did I lose points?" Taps "Practice Missed Questions" for targeted remediation. Values efficiency — won't do a full review if time is short.
Phase 6

Review & Growth ("The Teaching Moment")

Steps 6.1 → 6.4
This is where the real learning happens. The quiz was retrieval practice — the brain attempted to recall information. The review is where errors are corrected and schemas are built. Research (Roediger & Karpicke, 2006) shows that test + feedback produces dramatically better retention than test alone. Skipping review cuts learning value in half.
6.1
Review Mode Opens (Same Two-Column Shell)
Quiz shell with REVIEW badge, read-only, all feedback visible

The same two-column layout loads in review mode. Left column: question stem (read-only). Right column: all options annotated (correct = Cobalt highlight, user's wrong choice = Amber highlight, others dimmed) + full rationale panel always expanded. Navigation is free — palette shows correct/incorrect/skipped with filter pills. "REVIEW" badge in header (Amber background). No timer. No submit button.

Emotional state Reflective. Lower stress than active quizzing. Learning mode activated. "Let me understand where I went wrong."
Cognitive load MEDIUM. Processing explanations and building corrected mental models. Two-column layout helps: reference question (left) while reading rationale (right).
User action Typically filters to "Incorrect only" first. Reads each wrong answer's rationale. May tap Wiki links. Navigates via palette or Next button.
Drop-off risk HIGH for undergrads (low motivation to review). LOW for retakers (obsessive reviewers). Gated progression not needed here — but "X of Y reviewed" progress indicator encourages completion.
6.2
Question-by-Question Review Loop
User navigates through each question with full feedback

For each question: user reads stem (left) → sees annotated options + rationale (right) → absorbs the learning → navigates to next. Average time per question in review: 5–15 seconds for correct answers, 20–45 seconds for incorrect answers. Wiki links open in a slide-over panel (not a new page) so the user stays in the review flow.

6.3
Review Completion
User finishes reviewing or exits voluntarily

After last question or ✕ exit: returns to Results Dashboard. If user reviewed all incorrect questions: "You've reviewed all missed questions ✓" confirmation. CTA shifts emphasis: "Practice These Again" (primary) → creates new Focused Review with only the missed questions.

6.4
Expected Outcome After Review
What the user should feel and know
User should feel:
"I understand why I got those wrong." Not punished — educated. Closure on this session. Motivated to return (the growth delta showed improvement is possible).
User should know:
Which concepts they're weak on. Why their wrong answers were wrong (not just which were wrong). Where to go deeper (Wiki links visited). What to practice next.
Phase 7

Re-engagement Loop ("The Return")

Steps 7.1 → 7.3

The session is complete. The goal now is to create conditions for the next session. This phase exists between sessions — hours or days later.

7.1
Heatmap Updates
Taxonomy nodes change color based on session performance

Session results immediately update the Heatmap. Topics practiced move toward green (if mastered) or stay amber/red (if still weak). This visible change is the compounding reward — "I can SEE my map getting greener." Next time the user opens the app, they see the updated terrain.

7.2
Camp Trail Advances
Next day unlocks if user completed a Camp session

Camp Mode users see "Day 15 ready" on next app open. The trail provides the external structure that overcomes decision fatigue — users don't have to choose what to study, the trail chooses for them.

7.3
Re-engagement Triggers
Push notifications, Campfire activity, exam countdown

Next-day push: "Day 15 is ready — Accessibility (BP 344)." Inactivity nudge (72 hours): "Your Readiness Score hasn't moved in 3 days. One quick session?" Campfire social: "Maria from your batch just scored 88% on Storm Mode." Exam countdown: "46 days to ALE. You've completed 14 of 60 trail days." Each deep-links to the appropriate entry point → Phase 1 restarts.

Weeks 1–3

Build the unified two-column quiz shell. Config object system. Intro screen (Slide 1 only). Immediate feedback for Camp Mode. Results Summary with score + breakdown. Basic review mode. Ship Camp Mode and Chill Mode.

Phase B — Learning Modes
Weeks 4–5

Topic picker (Slide 2). Subject Mode + Focused Review. Adaptive difficulty engine. Confidence rating. Wiki link integration. Blindspot Protocol pre-selection. "Practice Missed" auto-session creation.

Weeks 6–8

Timer system (bar + countdown + countup). Question palette. Bookmark/flag. Deferred feedback. Pre-submission review grid. Storm Mode + Full Exam Sim + Extended Practice. Custom Session (Slide 3). Micro-breaks. Strikethrough. 24-hour delayed results. Offline support.
