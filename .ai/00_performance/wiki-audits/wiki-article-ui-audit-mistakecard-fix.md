# Wiki Article UI Audit — MistakeCard/MistakeList Prop Mismatch Fix

**Date:** 2026-05-04
**Agent:** Hermes (deepseek-v4-pro)
**Branch:** codebase-modernization-batch1-2

---

## 1. Summary

### What was audited
The full Wiki article rendering pipeline for custom UI components, triggered by user report that "common mistakes" UI components were empty on `/dashboard/wiki/lea-hist-001-03-core-concept` while ExamTip, Warning, and ArticleMedia rendered correctly.

### Root cause found
**Prop name mismatch (Mapping issue — classification #3).** The `WikiMistakeCard` component destructured props using the OLD naming convention (`number`, `title`, `wrongValue`, `correctValue`, `explanation`, `sourceRef`), but 154 out of 165 articles in the corpus use a NEW naming convention (`mistake`, `correction`, `context`) generated by the compose step. Additionally, 9 articles use a BODY convention (`title`, `body`). This caused all received props to be `undefined`, resulting in empty renders.

### What was fixed
- `WikiMistakeCard.tsx` now normalizes all three prop conventions into the canonical internal shape
- `WikiMistakeList.tsx` now passes index through for auto-numbering, accepts `items` as alias for `mistakes`
- `types/wiki.ts` updated with `WikiMistakeCardRawProps` union type

### What was intentionally not changed
- Other components with prop variance (KeyValues, ComparisonTable, WikiExamTable) — not reported as broken
- The renderer pipeline, MDX compilation, or fallback system
- Article content or data generation

### Styling fixes
None needed.

### Fallback fixes
Added safe defaults for all required fields:
- `number` defaults to index + 1
- `title` defaults to "Common Mistake"
- `wrongValue` defaults to "Common error"
- `correctValue` defaults to "Review the correct approach"
- `explanation` defaults to empty string
