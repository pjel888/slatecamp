## Phase 5 — Analytics Performance Analysis

**Finding:** `force-dynamic` is legitimately required — the analytics page uses `cookies` for Supabase auth. Removing it causes a Next.js static generation error.

**Root cause of 44s p95:** 25 independent async server components, each calling `getXData()` from `src/lib/actions/analytics.ts`. Each call creates a Supabase client and calls `getUser()` independently. Estimated 40+ database round-trips for a single page load.

**Low-risk optimizations possible (NOT implemented — for Batch 4):**
1. Create a shared `AnalyticsDataLoader` that calls `getUser()` once and passes the user to all sections
2. Use `Promise.all()` to parallelize independent Supabase queries within sections
3. Add `unstable_cache` with reasonable revalidation tags where data freshness allows

**High-risk optimizations (NOT recommended for Batch 4):**
- Rewriting analytics architecture
- Changing route-level auth
- Replacing the data model
- Collapsing all 25 sections into one component
