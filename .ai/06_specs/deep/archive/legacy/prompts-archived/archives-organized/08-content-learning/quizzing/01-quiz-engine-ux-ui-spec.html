Section 01

The Core Argument: One Shell, Many Modes

The problem today: SlateCamp has 8 exam modes with fragmented UIs. Subject Mode looks different from Camp Mode. Storm Mode has a different layout from Full Exam Simulation. There is no architectural reason for this — it creates maintenance debt, cognitive friction, and brand inconsistency.

The evidence is overwhelming: AMBOSS, UWorld, and every successful exam prep platform uses one quiz shell that adapts behavior through configuration flags — not separate interfaces. The difference between "study mode" and "exam simulation" is not layout. It is: (1) when feedback appears, (2) whether the timer is visible, (3) what navigation is permitted, and (4) what happens after submission. Those are boolean flags in a config object, not separate codebases.

The Unified Architecture

Every exam mode passes through the same three-phase pipeline. The config object controls behavior at each phase.

Phase 1

Session Setup

1–3 slides depending on mode. Collects user preferences, loads config, and initializes the session.

Phase 2

Active Quiz Shell

Identical layout for ALL modes. Config flags toggle timer, feedback, navigation, and palette.

Phase 3

Results + Review

Score reveal, performance breakdown, question-by-question review. Same shell, different depth of data.

§0

Immutable Layout Law

Two-Column Question Screen — Always

On desktop and tablet (≥768px), the active quiz screen is always a two-column layout: question stem on the left, answer options on the right. This is non-negotiable. The layout never shifts, never stacks, never rearranges between questions or between modes. A student answering question 1 sees the same spatial layout as question 200.

Left Column (50%)

Question number + stem, images/diagrams (if any), topic breadcrumb, confidence rating (learning modes)

Right Column (50%)

Answer options (A–D), submit/next button, feedback panel (slides in below options after submission in immediate mode)

Mobile only (<768px): Stacks vertically — question on top, options below. This is the ONLY exception.

Why: Layout shifts during high-focus activity destroy flow state. The brain builds spatial memory of "where to read" and "where to answer." Breaking that contract forces re-orientation on every question — extraneous cognitive load we refuse to impose.

The Config Object

Every mode is defined by this single configuration object. The quiz shell reads it and adapts. No conditional UI branches — only config-driven rendering.

interface QuizSessionConfig {
  mode: 'camp' | 'chill' | 'subject' | 'focused' | 'custom' | 'storm' | 'fullexam' | 'extended';

  // Setup phase
  setup: {
    slides: SetupSlide[];         // Which setup screens to show
    defaultQuestionCount: number;  // Pre-filled count
    allowCountChange: boolean;     // Can user change count?
    showSubjectPicker: boolean;    // Show subject/topic filter?
    showDifficultyPicker: boolean; // Show difficulty selector?
    showReadinessPrompt: boolean;  // Show "How are you feeling?" slide?
  };

  // Timer
  timer: {
    enabled: boolean;
    visible: boolean;              // Timer exists but may be hidden
    mode: 'countdown' | 'countup' | 'bar' | 'hidden';
    totalSeconds: number | null;
    perQuestion: boolean;          // Per-question vs per-session
    pausable: boolean;
    warningThresholds: number[];   // [0.75, 0.90, 0.95]
  };

  // Feedback
  feedback: {
    timing: 'immediate' | 'deferred' | 'none';
    showExplanation: boolean;
    showCorrectAnswer: boolean;
    showConfidenceRating: boolean;
    gatedProgression: boolean;     // Delay Next button 3s after feedback
    explanationDepth: 'brief' | 'full' | 'with-wiki-link';
  };

  // Navigation
  navigation: {
    model: 'linear' | 'free' | 'linear-with-skip';
    backAllowed: boolean;
    questionPalette: boolean;
    bookmarkEnabled: boolean;
    skipEnabled: boolean;
    confirmBeforeSubmit: boolean;
  };

  // Difficulty
  difficulty: {
    mode: 'static' | 'adaptive' | 'user-selected';
    targetAccuracy: number;        // 0.85 for adaptive
    initialLevel: 'easy' | 'medium' | 'hard' | 'mixed';
  };

  // Post-quiz
  results: {
    showImmediately: boolean;      // vs delayed (Full Exam Sim)
    delayHours: number;            // 0 for immediate, 24 for full exam
    showPercentile: boolean;
    showSubjectBreakdown: boolean;
    showGrowthDelta: boolean;
    showReviewCTA: boolean;
  };
}

Section 03

Universal Flow: Entry Point

Every quiz session in SlateCamp starts from one of these entry points. Regardless of origin, the flow converges to the same Session Setup pipeline.

Entry Points → Session Setup

E1
Dashboard "Start Session" Button
The primary CTA on the home dashboard. Shows today's Camp Trail day or the user's last active mode. Tapping goes directly to the mode's Session Setup Slide 1.
Button states
  • Camp Trail enrolled: "Start Day 14 — Structural Systems" → opens Camp Mode setup
  • No trail enrolled: "Start a Quiz Session" → opens Mode Selector
  • Session in progress: "Resume Session (Q 12/20)" → opens Active Quiz at last question
E2
Heatmap Node Tap → "Practice This Topic"
User taps a topic node on the Taxonomy Heatmap. Bottom sheet appears with topic name, mastery status, and "Practice This" CTA. Tapping CTA pre-configures Subject Mode or Focused Review with that topic pre-selected.
Behavior
  • Red/Amber node → Opens Focused Review with topic pre-filled
  • Green node → Opens Subject Mode for maintenance practice
  • Grey (unexplored) node → Opens Subject Mode with "Start exploring" framing
E3
Camp Trail Day Card
Each day on the Camp Trail has a card with the session configuration. Tapping "Start Day" opens Camp Mode with that day's config pre-loaded (topic, question count, difficulty — all set by the trail algorithm).
E4
Mode Selector (Direct Launch)
Accessible from the bottom-right FAB button (➕) or from the dashboard quick-actions row. Presents all 8 modes in a grid. This is the universal fallback entry point.
Mode selector layout
  • 2-column grid on mobile, 4-column on desktop
  • Each mode card shows: icon, name, 1-line description, badge (Learning/Exam/Custom)
  • Cards are grouped: "Learning Modes" (Camp, Chill, Subject, Focused) and "Exam Modes" (Storm, Full Exam, Extended) and "Your Way" (Custom)
  • Tapping a card opens that mode's Session Setup Slide 1
E5
Post-Quiz Review → "Practice These Again"
After completing a quiz review, the results dashboard offers a CTA to re-practice missed questions. This auto-creates a Focused Review session with only the missed questions loaded.
E6
Push Notification / Deep Link
Re-engagement notifications like "Your Camp Trail day is ready" or "You have 5 flagged questions to review" deep-link directly to the appropriate session setup.

Section 04

Universal Flow: Session Setup Slides

After entry, every mode passes through 1–3 setup slides. The slides are modular — the config object determines which ones appear and in what order. Each slide is a full-screen overlay with a single purpose.

Design rule: Each setup slide has exactly ONE question and ONE primary action. No slide asks two things. No slide requires scrolling. Setup should feel effortless — if it takes more than 10 seconds per slide, the slide has too many options.

Question Screen — Complete Element Inventory (Two-Column Desktop)
  • Top bar (full-width, above both columns): Exit button (✕ Exit), progress bar (4px, Cobalt fill), fraction indicator (DM Mono 11px), mode badge (DM Mono 8px uppercase), timer (per config), bookmark toggle (⚑), palette trigger (▦). Height: 48px.

  • LEFT COLUMN contents (top to bottom):
  • Topic breadcrumb — DM Mono, 9px, uppercase, muted. Shows taxonomy path: "Structural Design › Foundations › Shallow Foundations"
  • Question number — DM Mono, 11px, Cobalt, 500 weight. "Question 8"
  • Question stem — Inter, 15px, 400 weight, line-height 1.8. Full column width with 32px padding.
  • Image/diagram (conditional) — If question has visual: rendered below stem, max-height 280px, border-radius 10px, click-to-zoom overlay. If no image: area collapses, no placeholder shown.
  • Confidence rating (conditional) — Below image or stem. Only if config.feedback.showConfidenceRating === true. Horizontal pills: Guessing / Somewhat sure / Very sure. Separated from stem by 1px border-top.
  • RIGHT COLUMN contents (top to bottom):
  • "Select your answer" label — DM Mono, 9px, uppercase, muted.
  • Answer options A–D — Stacked vertically. Each row: 48px min-height, full column width, entire row clickable. Radio + letter (DM Mono 11px) + text (Inter 13px). Selected: Cobalt Light bg + Cobalt border. 10px gap between rows.
  • Submit/Next button — Below options, separated by 1px border-top + 20px padding. Cobalt primary, 44px height, right-aligned. Disabled (grey) until answer selected.
  • Previous button — Left-aligned ghost button, same row as Submit. Hidden if backAllowed === false.
  • Bottom bar (full-width, below both columns): Redundant navigation for quick access: ← Previous | Q 8 of 20 | Submit →. On mobile this is the ONLY navigation (sticky bottom). On desktop it's secondary — primary actions are within the right column.
  • Column padding: 32px all sides for desktop. 20px for tablet. On mobile (stacked): 16px horizontal.

Universal Flow: Submission

What happens when the user reaches the last question or manually ends the session.

S1
Last Question Answered
After answering the final question, the "Next" button text changes to "Finish Session →" (learning modes) or "Submit Exam →" (exam modes). Visual treatment: orange accent on the button to signal finality.
S2
Pre-Submission Review Screen (Exam Modes Only)
For Storm, Full Exam, and Extended: a full-screen summary appears showing all questions in a grid. Each cell shows answered/unanswered/flagged status. User can tap any cell to jump back to that question.
Pre-submission screen elements
  • "Review Your Answers" heading (H2, Syne 800)
  • Summary stats: "48 answered · 2 unanswered · 3 flagged" (DM Mono, 11px)
  • Question grid: 10 columns, cells are 36×36px with number. Colors: Cobalt (answered), Grey border (unanswered), Orange (flagged)
  • "Show unanswered only" / "Show flagged only" filter pills
  • Tapping a cell jumps back to that question — user can change their answer, then return here
  • "Submit Exam" primary CTA + "Keep Reviewing" secondary
  • For Full Exam Sim: "⚠ Once submitted, you cannot change answers. Your results will be available in 24 hours." warning in amber box
S3
Submission Confirmation Modal
A centered modal asks for final confirmation. Learning modes: "End this session? Your progress is saved." with "End Session" + "Keep Going" buttons. Exam modes: "Submit your exam? This cannot be undone." with "Submit Exam" (destructive style, but amber not red) + "Go Back" buttons.
S4
Processing Animation (500–800ms)
Full-screen overlay with the SlateCamp logo mark + "Calculating your results..." text. This is an emotional buffer — it separates the stress of answering from the score reveal. Not a loading spinner — a deliberate breath.
S5
→ Results Dashboard (or Delayed Confirmation)
For all modes except Full Exam Sim: proceeds directly to the Results Dashboard. For Full Exam Sim: shows "Your exam has been submitted. Results will be available in 24 hours. We'll send a push notification." with a CTA to return to the dashboard.

Section 09

Universal Flow: Exit Patterns

How does a user leave a quiz session? Every exit path must be deliberate — no accidental data loss.

Mid-Session Exit (Learning Modes)

User taps ✕ in the header during a Camp, Chill, Subject, Focused, or Extended session.

1. Confirmation modal appears: "End this session?"
2. Body text: "You've answered 12 of 20 questions. Your progress is saved — you can pick up where you left off."
3. Actions: "End & See Results" (primary) + "Keep Going" (ghost)
4. If "End & See Results": shows Results Dashboard for the 12 answered questions
5. Session state saved to server — user can resume if they return within 24 hours
Mid-Session Exit (Exam Modes)

User taps ✕ in the header during a Storm, Full Exam, or timed Custom session.

1. Confirmation modal appears: "Leave this exam?"
2. Body text: "Leaving will pause your timer. You can resume within 30 minutes — after that, the session auto-submits."
3. Actions: "Pause & Leave" (secondary amber) + "Continue Exam" (primary)
4. Note: "Continue Exam" is the primary CTA — we nudge the user to stay, not quit
5. Auto-submit after 30min timeout with push notification: "Your exam was auto-submitted."
Session Resume Flow

When a user returns to SlateCamp with an incomplete session:

Dashboard banner: "You have an unfinished session" card appears at the top of the dashboard.
Banner content: Mode badge + "Structural Systems · 12/20 answered · Started 2 hours ago"
Banner CTAs: "Resume" (primary) + "Discard" (ghost, with confirmation modal)
Resume behavior: Opens quiz shell at question 13 (the next unanswered). Timer resumes from where it paused (exam modes).
Expiry: Learning mode sessions expire after 24 hours. Exam mode sessions expire after 30 minutes. After expiry: auto-submit with available answers.

Section 12

Accessibility Requirements

Semantic Structure
Each question uses <fieldset> + <legend> wrapping the question stem and radio inputs. Question stem uses <h2> for screen reader navigation. Answer options use native <input type="radio"> within a radio group — arrow keys navigate between options. Focus management: on question change, focus moves programmatically to the question heading.
Color & Contrast
WCAG 2.1 AA minimum. All body text: 4.5:1 contrast. Large text and UI components: 3:1. Charcoal (#1A1A2E) on white = 15.4:1. Color is NEVER the sole indicator — all feedback uses icon + text + color. Palette cells use shape + number + color. Focus indicators: 2px solid outline, 3:1 contrast against adjacent colors.
Touch Targets
44×44px minimum for all interactive elements (WCAG 2.1 AA). Answer option rows: full-width × 48px minimum. Buttons: 48px height minimum on mobile. Palette cells: 36px desktop, 44px mobile. Spacing between adjacent tap targets: minimum 8px.
Timer Accessibility
Timer warnings use aria-live="assertive" with role="alert" ONLY for critical thresholds (5 min, 1 min). Routine timer updates: aria-live="off". Keyboard shortcut T announces time remaining via screen reader. Progress bar timer: role="progressbar" with aria-valuenow and aria-valuemax.

Section 13

Mobile-First Specifications

Device context: Median SlateCamp user is on a mid-range Android (Realme, Samsung A series), 6–6.5" display, 4G connection. 75% of quiz sessions happen on mobile. Quiz UI MUST be designed mobile-first.
Mobile layout specifications
  • Horizontal margin: 16px both sides. Total content width: screen width − 32px.
  • Question stem: 14–15px. Full width. Line-height 1.7.
  • Answer options: Full width. 48–56px row height. 12px gap between options. Entire row is tap target.
  • Bottom nav bar: 56px + safe area inset. Sticky to viewport bottom. White bg, 1px top border.
  • Question palette: Bottom sheet. Half-height initial, swipe-up for full. Overlay with backdrop dim (rgba(0,0,0,0.3)). Close on swipe-down or backdrop tap.
  • Feedback panel: Slides up from below options. Max-height 50vh. Scrollable if content exceeds. Rounded top corners (16px).
  • Thumb zones: Primary actions (Submit, Next) in bottom 40% of screen. Timer/exit in top zone (intentional friction for accidental taps). Answer options in natural center-to-bottom zone.
  • Landscape orientation: Supported but not optimized. Quiz shell adapts but doesn't rearrange. Most users stay portrait.
  • Offline handling: Answers cached locally in IndexedDB. "Offline" banner appears at top (amber bg, 10px font). Auto-syncs when connection returns. No data loss.

Section 15

Error & Edge States

Connection lost mid-quiz

Amber banner at top: "You're offline. Answers are being saved locally." Quiz continues normally. When connection returns: banner changes to "Back online. Syncing..." then auto-dismisses. No data loss.

App backgrounded during exam

Learning modes: session pauses indefinitely. Exam modes: timer pauses for 30 minutes max. After 30min: auto-submit with answered questions. Push notification: "Your exam was auto-submitted."

Question fails to load

Skeleton loader for 3 seconds. If still failing: "This question couldn't load. Skip to the next one?" with "Skip" primary and "Try Again" secondary. Question marked as unanswered, not counted against score.

No questions available for selected topic

On Setup Slide 2: topic chip is disabled (greyed out) with tooltip: "No questions available yet." If ALL topics in a subject are empty: subject row shows "Coming soon" badge.

User tries to submit without answering

Submit button is disabled (grey) until an option is selected. In exam modes with skip: "Skip →" ghost button is always available. No modal or alert needed — the disabled state is sufficient.

Battery low during exam

At <15% battery: subtle amber pill appears: "Low battery. Your progress is auto-saved." No action required — just reassurance that nothing will be lost.

Timer expires during exam

At 0:00: auto-submit all answered questions. Full-screen: "Time's up! Your exam has been submitted with [X] of [Y] questions answered." → Routes to Results (or 24-hour confirmation for Full Exam).
