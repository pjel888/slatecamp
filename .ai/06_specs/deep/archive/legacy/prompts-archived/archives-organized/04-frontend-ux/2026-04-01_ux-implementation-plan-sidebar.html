Section 01

Current State Audit

Three UX problems were identified in the controls column of the newly split dual-column sidebar. The information column (right) is unaffected.

Problem 01 — High

Inverted Data Entry Sequence

Zoning Classification sits below Lot Parameters. The zoning governs Table VIII.1 values (PSO, ISA, USA, TOSL, BHL, FLAR). Users manipulate sliders before setting the constraint that defines what those sliders mean.

Problem 02 — High

Preset & Violation Visual Clutter

10 equally-weighted pill buttons across two sections create a "wall of options." Presets (configuration loaders) and Violations (educational scenarios) look identical except for border color — no semantic differentiation.

Problem 03 — Medium

No Progressive Disclosure

All controls are visible simultaneously on load. Novice users (Anxious First-Taker persona) see preset shortcuts before they understand the primary controls. No distinction between novice path and expert path.

Section 03

Proposed Information Architecture

Reorder follows the principle of dependency-first, shortcuts-second. The governing constraint (zoning) comes first, primary manipulation controls second, and power-user shortcuts last behind collapsible sections.

1
Zoning Classification Context setter — governs Table VIII.1 values
2
Lot Parameters Primary controls — width, depth, RROW sliders
3
Presets Collapsible — compact chips for quick configuration loading
4
Violation Case Studies Collapsible — amber scenario cards with descriptions
Constraint preserved: The dual-column layout (controls left, information right) is unchanged. Only the internal ordering and component design within the controls column is modified.

Section 05

Design Decisions & Rationale

5.1 — Zoning at Top

Decision

Move Zoning Classification to first position

In PD 1096, zoning classification is the governing constraint. It determines which Table VIII.1 row applies — setting PSO, ISA, USA, TOSL, BHL, and FLAR values. Placing it first mirrors the real architectural workflow: classify the lot, then set dimensions, then evaluate compliance. This matches Nielsen Heuristic #2 (match between system and real world).

5.2 — Presets as Compact Chips

Decision

Replace scattered pill buttons with compact mono-spaced chips in a collapsible section

Presets are power-user shortcuts, not primary controls. The current layout gives them top-level visual weight. Compact chips reduce vertical space by ~60%. Collapsing by default removes them from the novice path. Monospaced typography signals "code/configuration" — appropriate for loading predefined lot scenarios. The Reset button moves to the section header, reducing chip count from 6 to 5.

5.3 — Violations as Amber Scenario Cards

Decision

Replace red-bordered pills with amber-toned cards that include micro-descriptions

Red borders signaled "error" — wrong semantics for educational scenarios. Amber (the SlateCamp signal for in-progress / attention-needed) correctly frames these as "learning opportunities." Adding one-line descriptions helps the Anxious First-Taker persona understand what each violation demonstrates before clicking, reducing cognitive load. The border-left accent pattern matches the SlateCamp card system.

5.4 — Progressive Disclosure via Collapsibles

Decision

Wrap Presets and Violations in Shadcn <Collapsible> components

Novice users see: Zoning → Lot Parameters. That's it. Two clear sections, no confusion. Expert users expand Presets and/or Violations when ready. This follows Mayer's Coherence Principle (don't show information that isn't needed for the current learning task) and Nielsen Heuristic #7 (flexibility and efficiency of use).

Section 06

Implementation Phases

Phase 1 — Reorder
  • Move <ZoningClassification /> above <LotParameters /> in the controls column render tree
  • Add helper text: "Sets Table VIII.1 development controls" below dropdown
  • Verify Table VIII.1 Reference card in info column updates on zoning change
  • Test mobile stacking (single column at < 768px)
Phase 2 — Presets Redesign
  • Convert pill buttons to compact chips: h-8 px-3 rounded-md border font-mono text-xs
  • Wrap in <Collapsible> from Shadcn/Radix
  • Move Reset to section header row (ghost button)
  • Add active state: bg-primary text-primary-foreground border-primary
  • Persist collapse state in localStorage
Phase 3 — Violations Redesign
  • Convert red pills to amber-toned mini cards with border-l-2 border-l-amber-500
  • Wrap in <Collapsible> component
  • Write one-line descriptions for each violation scenario
  • Add active state: border-l-amber-600 bg-amber-100/70
  • Verify violation scenarios trigger the correct compliance overlay in the 3D canvas
Phase 4 — Polish & Accessibility
  • Audit spacing: 24px section gaps (space-y-6), 16px card padding
  • Verify monospaced typography on all section labels and numeric values
  • Check 44px minimum touch targets for all interactive elements
  • Test contrast ratios: 4.5:1 body text, 3:1 UI components
  • Run VoiceOver + TalkBack — verify focus order follows visual order
  • Add aria-expanded to collapsible headers

Section 08

Constraints & Boundaries

Preserved: The dual-column layout (controls left, information readouts right) is strictly preserved. No merging back to a single column. The information column (Lot Summary + Table VIII.1 Reference) is unchanged.
Preserved: All Zustand store bindings and state logic remain unchanged. This redesign modifies visual presentation and render order only — no functional changes to setLotWidth, setZoning, loadPreset, or loadViolation.
Preserved: On-demand rendering (frameloop="demand") and invalidate() patterns are unaffected. The sidebar restructuring is a DOM-only change with no 3D pipeline impact.
R3F constraint: No text rendering inside the 3D canvas. All labels, descriptions, and violation card copy remain in the 2D DOM sidebar panel.
