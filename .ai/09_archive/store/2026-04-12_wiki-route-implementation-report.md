## 4. Rationale for Architectural Decisions
- **Action Consolidation:** Unifying on `wiki-actions.ts` ensures that performance optimizations (like the `get_article_with_node` RPC) are used consistently and reduces maintenance overhead.
- **Structured Results:** Moving from boolean returns to `WikiActionResult` allows the UI to distinguish between different failure modes (e.g., unauthorized vs. network error) and provide specific feedback.
- **Client Error Component:** Using a dedicated client component (`WikiArticleError`) for server-side MDX failures allows for interactive recovery (refreshing) without bloating the main renderer.
- **Lib Move:** Moving `injectEIPrompts` from a component file to `src/lib` allows for clean unit testing without React dependencies.
