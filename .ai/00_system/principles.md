# .ai System Principles

**Last Updated:** 2026-04-17

## Core principles

1. **Truth before tidiness**
   - Fix misleading authority first.
   - Prefer accurate placement and labeling over cosmetic neatness.

2. **Documentation-first operations**
   - Audit the workspace before reorganizing it.
   - Record scope, intent, and constraints before structural cleanup.

3. **Audit-before-change**
   - Inspect what exists.
   - Identify drift, duplication, stale authority, and naming ambiguity before editing.

4. **Traceability over minimalism**
   - Historical context is valuable when it stays clearly historical.
   - If a file is preserved for lineage, mark it so readers cannot mistake it for current authority.

5. **Controlled archival is allowed**
   - Non-destructive does not mean “leave dangerous active-looking docs in place.”
   - Demote or archive misleading historical docs when provenance and references are preserved.

6. **Active vs preserved clarity**
   - Mark whether a file is active, bridge-only, preserved lineage, archive, or superseded.
   - Avoid silent replacement of older material.

7. **Minimal-risk organization**
   - Prefer indexes, source-of-truth docs, and bounded refresh passes.
   - Rename or rehome files only when ambiguity or risk justifies it.

8. **Operational consistency**
   - Keep numbered `.ai` folders authoritative.
   - Keep `.agents/skills/` as the Codex-discoverable skill layer, not a second governance tree.
