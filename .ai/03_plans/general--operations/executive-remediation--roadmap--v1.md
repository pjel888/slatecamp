# Executive Remediation Roadmap

## Highest-risk themes

- Broken bootstrap and weak validation gates
- Active security and data exposure risks
- Unsafe documentation authority
- `.ai` and state hierarchy conflicts
- High-risk admin and 3D architecture hotspots

## Critical blockers

- `TOOL-002` broken Bun bootstrap
- `TOOL-003` dual-lockfile drift
- `TOOL-004` missing app-wide CI gates
- `DOC-001` unsafe legacy authority doc
- `META-003` split state authority
- `DATA-001` public source-row exposure
- `SEC-002` vulnerable Next.js range

## Recommended sequence

### First

- decide authoritative package-manager/lockfile contract
- restore install/build/validation reliability
- patch critical framework/dependency risk
- demote unsafe legacy authority docs
- define `.ai` state and mirror ownership rules

### Second

- repair public data exposure and webhook idempotency
- regenerate current schema/policy truth
- add app-wide CI gates
- add AGENTS boundaries to missing doc/governance zones

### Third

- decompose admin authoring payload and boundary hotspots
- rationalize 3D Lab registry ownership and viewport screenshot cost
- stage stronger query/type/lint guardrails

## What must wait

- broad refactors unrelated to current risk
- physical `.ai` folder moves without approved migration sequencing
- wholesale design/system cleanup detached from the critical findings

## Human decisions required

- package-manager source of truth
- mirror payload source/generator strategy
- acceptable residual dependency risk during transition
- sequencing preference between admin and 3D architectural work after blockers are cleared

## Acceptance criteria

- a later implementation-approved run can execute this sequence without reopening the audit scope
