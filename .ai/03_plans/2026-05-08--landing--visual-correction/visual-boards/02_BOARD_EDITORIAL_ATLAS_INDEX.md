# Board 2 — Editorial Atlas Index

Status: visual direction board, no implementation

## Core idea

The landing behaves like a premium interactive publication or architecture index. It is the approved lead direction because it extends SlateCamp's existing editorial/typographic DNA and keeps the message legible before any atmosphere or motion.

The page uses large type, section numbers, coordinates, marginalia, and sparse mapped visuals to make SlateCamp feel like a serious architecture field guide.

## Reference lineage

Use as principles, not literal copies:

- Paradiso Institute — cultural/education-adjacent, expressive type and spatial labels.
- Razorpay Sprint 26 — strong numbered editorial system.
- Obys Agency — black field, sparse navigation, symbolic marks.
- T11 — bold type over cinematic field.
- Save.design — clear category/resource posture.

## Emotional target

- "This is an organized reference system."
- "The site has taste and authority."
- "I know where I am in the material."
- "This is for architecture people, not generic students."

## Hero composition

### Desktop

- Dark editorial canvas with dotted grid background.
- Very large headline, possibly spanning most of the viewport width.
- A sparse atlas coordinate system behind it.
- Small marginal text blocks:
  - LEA knowledge atlas
  - source notes where verified
  - wiki / practice / visual tools / analytics
- The visual field supports the type rather than competing with it.
- CTA is placed like an index action, not a SaaS button cluster.

### Mobile

- Big headline remains the main visual object.
- Marginal metadata collapses into one or two small lines.
- No crowded grid of labels.

## Visual language

Use:

- oversized type
- section numbers
- page/index markers
- small coordinates
- muted source/update metadata
- dotted grid
- thin separators and route lines
- confident asymmetry

Avoid:

- decorative 3D object as hero centerpiece
- product card or mockup
- multiple pill badges
- too many tiny labels that hurt mobile clarity
- academic dryness

## 3D/canvas behavior

3D is optional in this board.

If used:

- it is a subtle depth layer behind typography
- not a visible object/module
- behaves like spatial parallax or shifting coordinate field

This board can be more performance-safe because the brand impact comes from typography and editorial structure.

## Copy posture

The copy should feel direct and precise, not poetic overload.

Possible headline territory:

- "Know where architecture topics fit."
- "An atlas for the parts of review that feel scattered."
- "Find the topic. See the context. Choose the next step."

Subcopy territory:

- "SlateCamp organizes architecture concepts, references, visual explanations, and practice paths so review season feels less like guesswork."

CTA:

- "Open the atlas"
- "Browse the field guide"

## Section rhythm

This board uses a chapter/index rhythm:

- `00 / Orientation`
- `01 / When review feels scattered`
- `02 / The atlas model`
- `03 / Product paths`
- `04 / Trust boundaries`
- `05 / Start`

Each section should feel like a page in an authored publication, not a marketing module.

## Product truth handling

Product paths appear as indexed entries, not fake screenshots:

- `A / Wiki` — find explanations and related topics.
- `B / Practice` — check what stayed.
- `C / Visual tools` — see spatial rules where available.
- `D / Analytics` — revisit weak areas and activity signals.

This is honest and avoids overpromising shipped UI.

## Why this is not cheesy

It uses architecture-school/editorial discipline rather than literal 3D spectacle. It can feel mature if type, spacing, and motion are handled well.

## Risks

- Could become too dry or academic.
- Could lack enough visual magic if the field layer is weak.
- Could underuse the Three.js ambition.
- If the metadata looks like badges, it regresses into the rejected style.

## Approval criteria

Approve this board if the priority is:

- seriousness
- clarity
- editorial taste
- lower implementation risk
- less dependency on WebGL

Reject if it feels like a PDF cover, portfolio template, or dry institutional page.
