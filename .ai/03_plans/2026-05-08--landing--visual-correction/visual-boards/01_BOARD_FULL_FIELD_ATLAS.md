# Board 1 — Full-Field Atlas

Status: visual direction board, no implementation

## Core idea

The landing opens as an environment, not a module.

The user lands inside a dark, calm, navigable field of architecture knowledge: dotted grid, subtle depth, source-like marks, traces, and quiet atmospheric movement. In the approved direction, this field serves as atmospheric depth behind Board 2's editorial typography. Nothing is boxed inside a card.

This remains the strongest correction to the carded-3D failure as an atmosphere layer, but it is not the approved lead communication system.

## Reference lineage

Use as principles, not literal copies:

- Infinite Field — full spatial field; visual is the world, not a module.
- Where Worlds Take Shape — page begins as a place to enter, not a dashboard.
- Dirac — product concept expressed as abstract physics.
- Matter — cinematic restraint; confidence through atmosphere, not feature cards.
- Save.design — resource-category clarity and browsing posture.

## Emotional target

- "I can breathe."
- "There is a map here."
- "This was built by people who understand architecture and board-season anxiety."
- "I can find my way through scattered material."

## Hero composition

### Desktop

- Full-viewport dark field.
- Dotted grid/atmospheric background continues from current strongest asset.
- Large headline sits slightly left of center or lower-left, not trapped in a panel.
- Copy floats directly on the environment with strict restraint.
- Subtle field elements occupy depth across the entire viewport:
  - points
  - thin measured lines
  - faint section/plan traces
  - long arcs or routes
  - sparse coordinate labels
- CTA is simple and quiet.
- Nav is minimal and does not compete.

### Mobile

- Same field, reduced density.
- Headline first, with field visible behind/above.
- No attempt to show mini product UI.
- CTA visible without turning the hero into a card.

## Visual language

Use:

- dark graphite / deep navy / warm amber restraint
- dotted field
- faint mapped paths
- low-opacity architectural traces
- long spatial lines
- large negative space
- precise, small metadata labels
- slow parallax / pointer drift

Avoid:

- glass cards
- rounded hero container
- orbiting pills
- glowing neon gimmicks
- obvious blueprint clichés
- literal building model in a box
- fake app screenshot

## 3D/canvas behavior

The 3D layer is not an object showcase. It is the field.

Possible behaviors:

- points settle into a calm topology as the page loads
- faint lines connect only on pointer/scroll proximity
- depth changes slightly with cursor movement
- grid shifts subtly like a sheet in space
- visual density increases below the fold to lead into the atlas model

Fallback:

- CSS/SVG dotted field and gradient texture preserve the same composition.
- Reduced motion keeps a static atmosphere.

## Copy posture

Hero copy should be short.

Possible headline territory:

- "Find your way through architecture review."
- "Architecture knowledge, mapped for the moments you feel lost."
- "A calmer atlas for architecture knowledge."

Subcopy territory:

- "SlateCamp helps Filipino architecture students find concepts, source notes, visual explanations, and practice paths beside school and review season."

Micro-boundary:

- "Supplementary learning resource. No pass guarantees."

CTA:

- "Explore the atlas"
- "Start with the free atlas"

## Section rhythm after hero

1. Entry field — orientation and atmosphere.
2. Problem statement — scattered review material / less panic.
3. Atlas layer — how knowledge is organized.
4. Product paths — wiki, practice, 3D visuals, analytics.
5. Trust boundaries.
6. CTA.

The field should visually bleed into the second section so the page does not feel like separate SaaS blocks.

## Product truth handling

Do not show product UI in the hero.

Product proof appears later as:

- minimal real product snippets
- accurate product-path diagrams
- source/update metadata
- links to actual dashboard concepts

Use Board 3 for these sections.

## Why this is not cheesy

It does not rely on a named metaphor or literal architecture gimmick. It uses architecture's deeper emotional qualities:

- spatial orientation
- measured fields
- void/solid contrast
- scale
- sequence
- restraint
- precision

## Risks

- If over-animated, it can become a tech demo.
- If too abstract, users may not understand the product category.
- If labels become pills, it regresses into the rejected card style.
- If the hero copy is too poetic, it may lose conversion clarity.

## Approval criteria

Approve this board only if the mockup feels:

- immersive but calm
- architecture-adjacent without cliché
- high-end reference-site aligned
- clearly SlateCamp, not generic AI/edtech
- emotionally useful to an anxious student

Automatic rejection if the field is put inside a rounded frame.
