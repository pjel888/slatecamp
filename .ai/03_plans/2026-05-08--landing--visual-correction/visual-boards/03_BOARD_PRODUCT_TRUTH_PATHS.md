# Board 3 — Product-Truth Paths

Status: visual direction board, no implementation

## Core idea

The landing is structured around what SlateCamp actually lets a user do:

1. Find a concept.
2. Understand its context.
3. Check what stayed.
4. Revisit weak areas.
5. See spatial rules where visual tools are available.

This board is less about hero spectacle and more about avoiding fake marketing surfaces.

It is strongest for the middle/lower landing sections and should probably be combined with Board 1 or Board 2 for the hero.

## Reference lineage

Use as principles, not literal copies:

- Save.design — resource/product category clarity.
- Dirac — product proof comes from the core problem, not generic feature cards.
- Razorpay Sprint 26 — structured product sections after a strong opening.
- Matter — product detail follows brand atmosphere.

## Emotional target

- "This actually helps me when I am lost."
- "The product does what the page says."
- "I know what I can use it for beside school/review center."
- "This is reliable, not hype."

## Hero composition

Board 3 should not define the hero by itself unless paired with Board 1 or 2.

If used in hero, it should still avoid product cards:

- product paths appear as small atlas coordinates, not screenshots
- no quiz mockup
- no dashboard mockup
- no 3D module preview

## Product sections

### Path 1 — Find

Real product basis:

- wiki articles
- taxonomy-linked topics
- related topics
- source notes where verified
- updated/read metadata

Landing expression:

- an index/list/map of architecture terms and topics
- search/browse behavior
- source/update metadata

Avoid:

- official-source implication
- claiming every page has perfect source coverage

### Path 2 — Understand

Real product basis:

- article content renderer
- learning purpose/context
- related topics
- visual explanations and components

Landing expression:

- show how a topic becomes readable context
- use short excerpts or diagrams, not fake screenshots

Avoid:

- saying SlateCamp replaces primary documents

### Path 3 — Check

Real product basis:

- quiz hub
- practice modes
- immediate/deferred feedback depending on mode
- rationales in applicable modes
- confidence tracking
- topic/article mappings where available

Landing expression:

- "Practice checks what stayed."
- "Missed topics can point back to explanations when mappings are available."

Avoid:

- fake question card as if it is the actual interface
- SRS/active recall jargon
- "every missed answer becomes..." absolute claim

### Path 4 — Revisit

Real product basis:

- weak nodes
- readiness signals
- analytics
- recommendations
- study activity heatmap

Landing expression:

- "See signals that help you decide what to review next."
- "Use weak-topic analytics as a guide, not a guarantee."

Avoid:

- pass probability
- guaranteed readiness
- fake score jumps

### Path 5 — See

Real product basis:

- 3D Lab exists and is entitlement-gated
- limited currently visible modules
- larger registry/roadmap exists but should not be described as shipped

Landing expression:

- "Available visual tools help spatial rules become easier to see."
- "Access depends on account/plan/entitlement."

Avoid:

- full 3D Lab free after signup
- hundreds of modules shipped
- fake SVG lab card

## Visual language

Use:

- path diagram
- sequential route
- indexed entries
- restrained snippets
- source/update metadata
- actual product nouns
- honest access caveats

Important visual guardrail:

- If shown as quadrants or zones, they must read as sectional path fields, not cards.
- Do not add shadows, rounded containers, glass surfaces, hover-card behavior, or bento-grid spacing.

Avoid:

- bento grid
- dashboard collage
- fake UI cards
- gamified quiz tiles
- entitlement-misleading CTAs

## Section rhythm

Best used after a Board 1 or Board 2 hero:

1. Hero atmosphere / editorial identity.
2. Student problem.
3. Product-truth paths.
4. Trust and access boundaries.
5. CTA.

## Why this is not cheesy

It avoids spectacle and fake metaphors. It wins through honesty, structure, and usefulness.

## Risks

- As a standalone hero direction, it may be too plain.
- If visualized as cards, it becomes the current failed direction again.
- If too copy-heavy, it loses the premium reference-site feel.

## Approval criteria

Use this board as the product-proof system if:

- the hero already establishes enough atmosphere
- the product claims need strict legal/product accuracy
- the goal is to make landing sections match the real dashboard/app

Do not use this board as an excuse to bring back feature cards.
