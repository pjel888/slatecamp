## Purpose

This pack finishes the pre-implementation work for the corrected SlateCamp landing direction.

It exists because the previous landing prototype moved too quickly into code and risked repeating the rejected pattern: a tech-led hero, right-side/carded 3D visual, fake product-proof energy, and feature-inventory copy.

## Final direction

The approved relationship remains:

> **Board 2 is the voice and structure. Board 1 is the atmosphere. Board 3 is the proof.**

- **Board 2 / Editorial Atlas Index leads**: hero message, typographic hierarchy, indexed sections, first-impression category clarity.
- **Board 1 / Full-Field Atlas supports**: dotted field, quiet depth, measured arcs, subtle atmospheric motion, never the protagonist.
- **Board 3 / Product-Truth Paths proves**: Find / Check / See / Revisit sections grounded in actual Wiki, Practice, Visual Tools, and readiness behavior.

## Implementation-readiness verdict

**Ready for implementation after this pack.**

This verdict is based on the completed direction, artifact set, file-level plan, copy hierarchy, rejection rules, and verification gates. It does not approve the current prototype as final production design; the prototype remains reference/disposable code for the upcoming implementation pass.

## Non-negotiable rejection rules

Reject the implementation if any of these appear:

- right-side 3D card/module hero
- rounded hero visual container
- hero dominated by a WebGL object instead of editorial type and copy
- fake dashboard, fake quiz, or fake 3D Lab screenshots
- public hero copy that leads with SRS, active recall, adaptive algorithms, or quizzing methods
- pass guarantees, official-source implication, or outcome prediction
- product proof as generic bento/card grid above the fold
- public use of the internal Pokedex metaphor
- claim that full visual lab access is free unless entitlement/product flow proves it
