# 01 — Board 2 Case Studies and Brand-DNA Analysis

Date: 2026-05-08
Status: implementation input, no production code

## Executive finding

Board 2 should lead because SlateCamp is not trying to win attention as a visual effects demo. It is trying to make anxious architecture learners feel oriented, assured, and supported by a reliable reference system.

The strongest visual category is therefore not "3D hero". It is:

> **Editorial architecture atlas.**

The hero's primary visual object should be the typographic/index system itself. The atmospheric field can add depth, but the language and structure must do the communication work.

## Case study lessons

### 1. Paradiso Institute — institutional editorial field

Useful pattern:

- expressive central identity
- small marginal labels
- spatial asymmetry
- page as cultural/institutional map rather than product tour

SlateCamp implication:

- The hero can feel like an authored field guide: one dominant headline, one compact category line, and restrained marginal coordinates.
- Marginalia should feel like index marks, not SaaS badges.
- Use tiny metadata for `wiki`, `practice`, `visual tools`, `weak-topic signals`, and `source notes where verified`.

Constraint:

- Marginalia must never compete with the headline or turn into floating pill-label clusters.

### 2. Razorpay Sprint 26 — numbered editorial/product atlas

Useful pattern:

- indexed chapters
- product clusters presented as entries in a launch atlas
- strong rhythm from numbers and section logic

SlateCamp implication:

Use a numbered landing structure:

- `00 / Orientation`
- `01 / When review feels scattered`
- `02 / The atlas model`
- `03 / Product paths`
- `04 / Trust boundaries`
- `05 / Start`

Constraint:

- Sections need thesis statements, not generic feature names.
- The middle page can contain proof, but first impression must not become a card grid.

### 3. Obys — black field and sparse index tension

Useful pattern:

- dark field
- strong type
- restrained symbolic marks
- silence and negative space as premium signals

SlateCamp implication:

- A dark ink hero can work if the copy remains legible and category clarity appears within five seconds.
- The editorial type can be the spatial artifact. The field only supports it.

Constraint:

- Do not over-mystify. SlateCamp must still say what it is plainly.

### 4. Save.design — resource-site clarity

Useful pattern:

- quickly understandable resource category
- search/workspace framing
- clear content value before interaction detail

SlateCamp implication:

- SlateCamp must establish the category immediately: `architecture knowledge atlas`, `architecture field guide`, `source-aware learning resource`.
- The page can feel premium only after it first feels useful.

Constraint:

- Atmosphere cannot delay comprehension. A beautiful vague hero still fails.

### 5. Dirac — make invisible structure visible

Useful pattern:

- turns an invisible problem into visible product physics
- shows problem → organization/correction → proof

SlateCamp implication:

SlateCamp's product physics:

1. Review materials feel scattered.
2. Topics become mapped and searchable.
3. Practice and weak-topic signals show what to revisit.
4. Visual explanations help spatial rules become understandable.

Constraint:

- Never convert this into pass certainty. Use `signals`, `maps`, `next step`, and `where available`, not guarantees.

## SlateCamp brand-DNA implications

Board 2 fits because it extends the existing SlateCamp design and content universe:

- editorial / publication tone
- indexed/numbered sections
- dotted grids and measured lines
- dark ink and cobalt accents
- source-aware metadata
- compact, study-first density
- calm under pressure
- architecture-reference seriousness

`DESIGN.md` reinforces this direction:

- study-first over decorative effects
- signal-first hierarchy
- legible by default
- dense but breathable
- calm under pressure
- no hype, shame, or decorative reward loops
- no nested card stacks as page rhythm

## Why Board 2 must lead

### Board 2 fixes the actual failure

The prior failure was not just a bad 3D object. It was a communication hierarchy failure:

- visual device before message
- carded/right-side product-object logic
- feature-tour rhythm
- fake product-preview energy
- generic edtech/SaaS posture

Board 2 forces the page to make a language decision first.

### Board 2 is the lower-risk implementation direction

- works if WebGL fails
- works with reduced motion
- works in static SSR
- communicates in five seconds
- matches existing SlateCamp type/grid/source systems
- lets product proof appear later with truthful caveats

### Board 1 stays valuable but demoted

Board 1 should not be discarded. It becomes:

- dotted atmospheric depth
- faint resolving points
- subtle parallax
- low-contrast arcs and grid traces
- spatial continuity between hero and next section

Board 1 should never be:

- a protagonist 3D scene
- a right-side module
- a labelled product demo
- a floating glass card
- the reason users understand SlateCamp

## Section recommendations

### `00 / Orientation`

Goal: establish category and emotional relief.

- Eyebrow: `Architecture knowledge atlas`
- Headline: `Find where it fits. Know what to revisit.`
- Support: source-aware resources, visual explanations, practice paths, and weak-topic signals for learners with scattered materials.
- Visual: dark editorial field; large type; Board 1 atmosphere behind.

### `01 / When review feels scattered`

Goal: name the real student problem.

Use human language:

- notes, codes, PDFs, recordings, and mock-board results pile up
- familiar topics still feel uncertain
- the problem is not laziness; it is lack of orientation

### `02 / The atlas model`

Goal: explain the SlateCamp organizing principle.

Use path logic:

- find the topic
- understand where it belongs
- check what stayed
- return to what needs another pass

### `03 / Product paths`

Goal: Board 3 proof without card regression.

Use sectional entries:

- `A / Find` — Wiki, resources, related topics, source notes where verified
- `B / Check` — Practice, explanations, missed-topic mapping where available
- `C / See` — visual tools and lab modules where access/product availability supports it
- `D / Revisit` — readiness and weak-topic signals as study guidance

### `04 / Trust boundaries`

Goal: make the supplementary/legal posture explicit.

Use calm boundary copy:

- supplementary architecture resource
- not official
- no pass guarantees
- not primary instruction
- verify current requirements with primary authorities and qualified professionals

## Implementation implication

The implementation should not treat the existing `AtlasFieldHero.tsx` prototype as final. It should be refactored into a small Board 1 atmosphere or replaced with a CSS/SVG/R3F atmospheric layer that supports a Board 2 DOM-led hero.
