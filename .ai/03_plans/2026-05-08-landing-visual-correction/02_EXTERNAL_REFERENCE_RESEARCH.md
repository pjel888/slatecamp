# 02 — External Reference Research: High-End Three.js / Interactive Landing Patterns

Date: 2026-05-08
Status: research notes for visual correction

## Research scope

Sources inspected or researched:

- Awwwards Three.js/WebGL tags and individual site pages
- FWA homepage/listing where accessible
- Godly-style curated references
- Direct site inspection through browser and visual analysis
- Previously cited references from SlateCamp research notes

Some search surfaces were bot/CAPTCHA limited, so this research uses accessible direct site visits, award listings, and subagent browsing.

## Core finding

The best Three.js/WebGL landing pages do not treat 3D as a framed module preview. They use 3D/canvas as the site's atmosphere, stage, or world.

Cards can exist later. They do not define the first impression.

## Reference patterns

### 1. Full-bleed world / entry threshold

Representative references:

- Infinite Field — `https://www.infinitefield.xyz/`
- Where Worlds Take Shape — `https://paodao.fr/`
- ASTRODITHER — `https://astrodither.robertborghesi.is/`
- Rabanne Invictus Elixir — `https://invictus-elixir-experience.rabanne.com/`

Observed pattern:

- The hero is a world or threshold.
- The user is invited to enter/explore/travel.
- Copy is sparse.
- The visual is not framed inside a SaaS card.
- Motion and interaction create the brand feeling before feature explanation begins.

Implication for SlateCamp:

The hero should behave like entering an architecture knowledge field/atlas, not like previewing a feature widget.

### 2. Conceptual product physics

Representative references:

- Dirac — `https://www.dirac.com/`
- Matter — `https://www.matter.com/`

Observed pattern:

- The visual expresses the product's core problem/physics.
- Dirac uses waveform/acoustic distortion as the conceptual object.
- Matter uses cinematic visuals and brand atmosphere rather than feature cards.
- Product detail comes later.

Implication for SlateCamp:

SlateCamp's visual should express "orientation through architecture knowledge" — not show a fake dashboard. Possible product physics:

- scattered knowledge resolving into an ordered field
- architectural concepts becoming locatable
- source/reference layers aligning
- uncertainty turning into navigable structure

Avoid naming this as a cheesy concept. Treat it as behavior.

### 3. Editorial/brutalist spatial system

Representative references:

- Paradiso Institute — `https://paradisoinstitute.org/`
- Razorpay Sprint 26 — `https://razorpay.com/sprint/26`
- Obys Agency — `https://obys.agency/`
- T11 — `https://t11.com/`

Observed pattern:

- Typography is either huge and sparse or dense in a highly authored way.
- Sections are numbered or indexed.
- Tiny labels, counters, and coordinates feel like a system — not like feature badges.
- Density is graphic/editorial, not marketing blurbs.

Implication for SlateCamp:

Use atlas/editorial structure:

- chapter numbers
- coordinates
- section markers
- topic/path labels
- source/update metadata
- small marginal notes

But do not turn these into pill badges floating around a card.

### 4. Agency-grade spatial portfolio / studio rhythm

Representative references:

- Lusion — `https://lusion.co/`
- Locomotive — `https://locomotive.ca/en`
- ARKITEKWEB — `https://www.arkitekweb.com/`
- Save.design — `https://save.design/`

Observed pattern:

- Strong opening visual identity.
- Scroll cue / exploration language.
- Subsequent sections use clear rhythm and strong hierarchy.
- Cards may appear, but they are not the identity itself.
- Design relies on restraint, timing, and large compositional decisions.

Implication for SlateCamp:

The page can use product/resource modules later, but only after the page establishes a mature visual world.

## What high-end references avoid

They generally avoid these as first impression:

- right-side rounded 3D card
- static dashboard mockup
- generic bento grid immediately after hero
- multiple badges/pills in hero
- marketing-heavy subcopy density
- feature checklist above the fold
- literal screenshot collage as the visual idea
- "AI-powered" or mechanism-first explanation

## What high-end references use instead

They commonly use:

- full-bleed canvas or cinematic visual field
- sparse copy over/near the field
- a single strong entry CTA
- authored scroll rhythm
- numbered sections
- editorial labels
- large type as spatial object
- interaction prompts
- visual continuity across sections
- delayed product specificity

## SlateCamp-specific translation

SlateCamp is not a luxury perfume, concert, crypto, or studio portfolio site. It is an educational architecture resource platform. Therefore, do not copy their spectacle literally.

Translate the principles:

- Use atmosphere, not gimmick.
- Use architecture's spatial emotion, not blueprint clichés.
- Use source/trust metadata, not fake UI badges.
- Use real product primitives, not invented screenshots.
- Use calm authority, not hype.

## Strongest benchmark rules for SlateCamp

1. The hero visual must not be inside a rounded UI card.
2. The first viewport should feel like an environment or publication, not a SaaS feature preview.
3. Copy should be sparse and human.
4. Section rhythm should be authored: chapters/layers/paths, not generic feature blocks.
5. Cards are allowed only when they serve actual content/resource browsing, and preferably after the opening atmosphere is established.
6. 3D should evoke architecture through space, scale, light, precision, and navigation — not literal floating panels.
7. Product proof should reference real dashboard/wiki/quiz/lab behavior truthfully.

## Design takeaway

Do not ask, "What 3D object can we put in the hero?"

Ask:

- What spatial state does the user enter?
- What feeling does the page create before it explains features?
- How does the visual field make architecture knowledge feel navigable?
- How does the page remain calm enough for anxious students?
- How does the system reveal product truth without becoming a fake dashboard?
