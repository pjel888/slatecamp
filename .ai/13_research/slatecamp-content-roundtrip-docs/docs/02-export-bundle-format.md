# Export Bundle Format

Each article exports as a self-contained folder under `.ai/content-audit-export/`.

## Folder structure

```text
.ai/content-audit-export/
  manifest.json
  export-summary.json
  sync-state.json
  validation-report.json
  runs/
    <run_id>/
      run-log.json
  articles/
    <safe-slug>--<article_id>/
      original.md
      normalized.md
      candidate.md
      ui-blocks.json
      ui-block-edits.json
      parser-errors.json
      article-metadata.json
      linked-questions.json
      sources.json
      taxonomy.json
      component-usage.json
      component-suggestions.json
      compose-report.json
      compose-error.json
      diff-report.json
      diff-report.md
      push-report.json
      push-result.json
      conflict-report.json
      question-edits/
        <question_id>.json
        <question_id>.push-report.json
  component-inventory/
    components.json
    component-files.json
    component-usage-in-articles.json
    component-audit-report.json
    component-suggestions.json
    unknown-components.json
    component-fit-notes.md
```

Some sidecars only exist after their command runs or if an error/conflict occurs.

## `manifest.json`

The manifest includes both implementation compatibility fields and schema-parity fields:

```text
export_version
export_run_id
export_id
generated_at
export_started_at
export_completed_at
repo_path
supabase_project_ref
hash_algorithm: "sha256"
article_count
question_count
source_count
taxonomy_link_count
articles[]
skipped_unchanged[]
errors[]
warnings[]
```

Each `articles[]` entry summarizes article id, title, slug, bundle path, content hash, linked question hash, source hash, and row counts.

## Folder naming

New exports use `<safe-slug>--<article_id>` where the slug segment is sanitized and truncated. Missing slugs use `article--<article_id>`.

## `original.md`

Exact value of `wiki_articles.content`.

Rules:

```text
- Do not alter whitespace.
- Do not normalize line endings unless the implementation explicitly records it.
- Do not remove custom UI.
- Do not add comments.
```

## `normalized.md`

Human/AI-readable markdown with custom UI blocks replaced by safe placeholders.

Implemented placeholder example:

```md
[SLATECAMP_UI_BLOCK:ui_0001 component="RampSlopeExplorer" status="preserved"]
Extracted summary:
- Props: slope="1:12", width="1200mm"
- Text: Demonstrates slope and width cases.
[/SLATECAMP_UI_BLOCK]
```

The parser also accepts legacy `block_0001` placeholders during recomposition for compatibility.

## `ui-blocks.json`

Structured preservation of every removed custom UI block.

Includes:

```text
block_id
block_type
component_name
raw
raw_hash
start_offset
end_offset
props
props_json
props_text
children_raw
children_text
placeholder
placeholder_hash
parser_confidence
parse_status
status
warnings
```

## `ui-block-edits.json`

Reserved audit sidecar for future intentional UI block edits. Current milestone writes an empty edit log and does not allow automatic UI block mutation.

## `candidate.md`

Generated by compose step. It is the only content eligible for Supabase push after diff and stale checks.

## `article-metadata.json`

Contains article identity, row counts, status fields, and hashes:

```text
content_hash
original_content_hash
normalized_content_hash
candidate_content_hash
ui_blocks_hash
linked_questions_hash
sources_hash
hash_algorithm: "sha256"
```

## `linked-questions.json`

Contains all `questions` where `questions.article_id = article_id`, plus `linked_questions_hash`.

## `sources.json`

Contains all `wiki_article_sources` where `wiki_article_sources.article_id = article_id`, plus `sources_hash`.

## `taxonomy.json`

Contains rows from `wiki_article_taxonomy` and joined taxonomy node data from `taxonomy_tree`.
